# 09/44 本机文章草稿恢复整合 v3
位图09-local-article-recovery-v3.png已由内置imagegen生成并先于本轮UI实现保存。关联44本机备份草稿管理。v2候选51c0cc6a及全部证据不可改写；09、44及45组仍未完成。
恢复管理扫描必须将collection=article且editor_type=markdown的复杂字节草稿键映射到当前文章；普通Markdown笔记不进入WebView复杂草稿扫描。仅查资源元数据，不解密正文。孤立/未知/未确认记录保留并阻止备份，禁止宽泛忽略前缀。
旧原生文章草稿原键和值不删除。显式恢复/暂不恢复写入元数据回执；v2回执同时绑定已检查的明文摘要和原密文值SHA256，置于同一维护锁与代际检查下。Native只返回指定本机draft偏好键的密文指纹，不返回密文、明文或密钥材料。清单只读取回执元数据并核对密文指纹，不解密草稿正文或账户数据。指纹变化/回执损坏保留为待处理；不能凭过期明文摘要忽略后来修改。
兼容原version1回执。只有正常进入文章并实际核对旧草稿摘要后，才能升级为带密文指纹回执。有效已处理旧稿从活动pending集合中归档，仍通过明确“查看旧草稿”入口展示；不再使备份误报未知或永久阻塞。存在真正复杂恢复记录时仍阻止备份。
备份主页增加本机草稿入口。草稿管理页蓝色主题，待处理与已处理旧文章分节；无pending显示绿色提示。已恢复记录的文案为“已转入编辑器”，不能写“已保存”。暂不恢复显示“已选择暂不恢复”。旧稿保存原字节，仅改变索引/元数据分类。
点击查看旧草稿后才允许读取受限旧稿正文，先再次核对命名空间、正ID、维护代际、有效回执与密文指纹；采用只读Markdown WebView显示，默认预览，原始BOM/CRLF只在呈现时处理。无保存按钮。底部说明“这是已处理的旧稿，不会自动覆盖文章。”和返回列表。文章已删除或格式已改时仍可只读查阅旧稿，恢复操作不可用并解释；不静默重建已删文章。
原文章仍可用时，顶栏恢复旧稿按钮显示明确确认。退出只读运行时并等待退休后，重新核对当前文章和原记录，转入现有安全恢复/编辑流程；恢复只进持久编辑草稿，仍需手动保存。不能覆盖现有pending/未知恢复；后台/连接切换后旧确认不得写入新代际。
验证：新增MD文章复杂草稿可定位、普通笔记排除；有效回执不误阻塞、损坏/变更密文仍阻塞；不读正文/账户的清单协议；旧版回执升级；只读旧稿与明确恢复/原文变化/删除/代际边界；所有旧记录字节不变。实际ARM64 redroid核对Native指纹、草稿管理、无误pending的备份预检和旧稿读取、恢复及重启。继续新建/null-ID、保护、附件/外链、公开和剩余原型细节，不能据此宣称全页面完成。
