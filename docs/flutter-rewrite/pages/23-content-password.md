# 23 内容密码：实现前原型与协议

2026-11-05。先生成23-content-password.png并发送，再实现。与分享设置独立页面；浅蓝背景、资源卡、正文保护信息、白卡密码表单、独立移除操作。当前无密码只显示新密码/确认；已有密码增加当前密码与移除卡。所有密码按原始输入保留空格，不启用补全/建议/个性化学习，不写草稿/日志/安全存储。

真实owner GET /api/blogs/:id 返回 has_password/blog_id/blog_title/blog_type，必须核对实际ID和格式，不用列表预览推测保护状态。PUT /api/blogs/:id {new_password,current_password?} 设置/修改密码；不发送 blog_content，服务端负责读取并解密旧正文、按当前格式编码、重加密。移除使用 {new_password:'',current_password:实际密码}，未保护的资源不能把空密码当清除操作。此接口适用于blog（笔记/文章），不能套到book/document。普通阅读解锁与管理密码分开，不借公开share端点写私有资源。

无新密码长度策略则不凭空宣称服务限制，客户端按UTF8长度给合理1KiB请求上限且保留Unicode原串；不允许空新密码。设置/修改需二次输入一致；移除需确认正文不再需密码、公开分享保留。写成功后清除输入并读取实际保护布尔；布尔只能证明有无密码，不能证明具体新密码，须使用owner verify-password的实际验证且避免把正文保存到页面/磁盘。未知写结果不能自动再PUT：只读核对状态，用户可明确验证候选密码；不能把仍为protected=true当旧密码未变。回执与核对分开保存状态，离开有明确提示。

密码变动不自动重置编辑令牌，既有共享编辑仍需正文密码。公开标题/作者/标签可能被旧服务API暴露，不能承诺仅标题外所有信息加密。错误文案不直接显示响应/URI/原始异常。需覆盖正确/错误当前密码、原始空格和Unicode、清除/设置、未知结果与回执后核对失败、中英文320dp200%键盘和实际服务契约。当前为设计，尚未实现。
