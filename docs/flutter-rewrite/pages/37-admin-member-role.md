# 37 修改角色：实现前设计
2026-11-07。虚构示例，不代表实际操作完成。先有原型再实现。

展示账号、ID、当前角色；普通用户/管理员单选。无变化时禁用下一步。变更进入确认框，明确目标及旧→新角色；确认后单次PUT /api/admin/members/{id}/role，body仅role=0或1。成功再读列表核对，未知结果禁止自动重放，应刷新核对并由操作者重新选择。

原型底部“禁用状态示例”仅表达当前member_id等于目标时的替代状态，产品不显示示例标题，不会在reader-zhou的普通操作表单同时放当前账户假标签。自身角色禁止更改；服务端对配置内置管理员的保护仍须处理403，列表没有该标识，不能以名字猜测。401/403应清除受保护资料，显示权限信息及返回。确认请求中禁连点，退出/换会话拒绝迟到结果。

延续白卡蓝色、16dp边距、48dp目标；320dp/200%字体纵向滚动，账号与确认框可换行。覆盖取消无请求、same-role无请求、自身禁用、保护账号403、成功回读、状态期间变化、结果未知不自动重试与过期会话清除。隔离Go与redroid核对，禁止操作生产成员。
