# 39 SSH 主机详情、检测和删除：实现前设计

2026-11-07。先核对真实Go路由与实现，再用内置imagegen生成并查看39-admin-host-detail-delete-v1.png；图片及完整提示词已保存。两屏均为虚构数据。第38组仍在回归，本设计先行，不代表39实现或验收。

白色页头/深蓝字/蓝色动作，浅蓝主机卡显示名称、host:port、username、credential_name/auth_type、shell；无秘密。下方独立连接状态卡展示历史状态/时间与检测连接按钮；高级配置折叠区展示cwd和docker_socket_path，图中为展开状态，不能删除这两个字段。长地址/路径可换行，窄屏与大字体单列、全部滚动可达；编辑与红色删除动作在底部。

主机没有GET /ssh-hosts/:id接口。重新核对通过同一会话管理员鉴权后GET完整/ssh-hosts数组，按真实ID定位；详情不能从筛选后缺失推断已删除，不能读取一个列表失败就展示空主机。保存的status/last_check_time是历史值：unknown且无检测时间为尚未检测，unknown且有旧时间为状态未知。禁止从名称、时间或列表加载推测实时在线。

明确点击检测才POST /ssh-hosts/:id/test；不做进入页面/刷新/后台自动检测。不展示接口返回的原始message（可能含主机、命令或敏感诊断），只显示受控状态和时间。Go返回HTTP200/code0时，连接失败仍是data.status=offline，不应当解释为在线；checked_at须严格解析。Go对UpdateAssetSSHHostStatus错误未传播，因此“检测回执”和“服务器当前保存状态”是两个证据，需回读并区分，不能把回执当作保证已持久化。断线后结果未知，不自动重测，用户可明确读取当前保存状态核对，但不能据此确认上次测试结果。

删除主机先展示独立确认页：清楚说明只移除保存的记录，不删除远端服务器、不删除关联凭据。取消无请求；确认仅对重新核验且绑定ID/基线的目标发DELETE /ssh-hosts/:id。Go模型没有返回affected rows，code0只能表示请求被接受，不能声称影响恰好一行；后续GET核对当前列表，无自动重发。已知回执且回读失败只GET；断线未知先只读核对，保持未知结论。禁止按同名主机猜测原ID或对后来同名新ID进行补删。

检测/编辑/删除分别用独立动作状态，列表刷新/路由关闭/401/403/换空间或注销使旧结果失效并移除所属模态页。任何读取/写入前复核同一session/owner且role0；服务端鉴权最终判定。列表返回的credential只用于受限DTO即时判断是否提供，随后丢弃引用，详情与确认不持有原始响应或秘密。

40终端、41SSH文件、43Docker的按钮只在各自真实闭环路由接通后出现；本原型没有占位按钮。凭据明确查看/删除及资产加密设置还需独立原型/文档再实现，不以本设计替代。
