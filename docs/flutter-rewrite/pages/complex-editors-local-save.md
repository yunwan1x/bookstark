# 29—34 · 复杂 Web 编辑器的本地保存与恢复

实施前设计，接统一容器原型 `../../prototypes/flutter-rewrite-2026-11-04/29-34-complex-webview-v1.png` 和 `complex-editors-webview.md`。原型第三屏的未保存/离开对话框、单层标题与空间状态栏继续适用；引擎正文保持原有实际工具栏。前一版 a36b80fe/900 只是五种本地只读 WebView 的真实设备检查点，不代表完整编辑完成。

## 本轮范围

首先让已有本地笔记/文章中的六种真实 editor_type 使用类型正确的读取、保存、冲突与草稿恢复。Markdown API 不接收这些 JSON，HTML 专用 repository 也不伪装接收其他格式。所有原用户表、ID、时间、标签和附件保持原有数据。只读/无权限场景继续使用只读容器；随后接服务器、书籍、公开/共享、保护内容与附件导入导出，不以本轮代替总目标。

## 数据与提交

`ComplexNote` 绑定数据库身份、collection、id、kind、title、labels、updated_at 与完整原文 SHA。`LocalComplexNotesRepository` 在同一 SQLite 事务中重新读取完整基线并比较，再原子更新正确类型的 title/content/labels/updated_at；类型变更、软删除、集合变化、并发变更均停止保存。未修改保存保持原时间。真正提交并回读匹配后才向 Web host 确认冻结快照；JS dirty=false 本身不代表数据库已保存。文章重名等 SQLite 错误不覆盖原文，也不自动改标题。

保存先锁定交互，再冻结并校验有界分块快照，然后等待本机恢复日志的真实持久化确认，最后才提交 SQL。锁定期间必须拦截主文档与 PPT 子 frame 的鼠标、触摸、键盘、输入法、粘贴、拖放及再次 Ctrl+S；不是只灰掉 Flutter 保存按钮。保存完成或可重试错误后再恢复交互。快照确认协议仍须保留稍后输入，不能依赖界面锁代替版本保护。

## 恢复与结果未知

本轮仅本地非保护文档可持久化正文。使用现有专用加密恢复存储及 Android commit 屏障，独立 `bookstark.complex-*` 命名空间含数据库、collection、kind、id，不使用 Web localStorage/IndexedDB。正文按实际 UTF-8 5MiB/20MiB边界校验。记录包含完整草稿、基线身份/元数据/摘要和 pending 标记，避免复制两份 20MiB 原文；不包含账号 token、密码或任意文件路径能力。

开始提交前 pending 必须落盘。提交后回调丢失、进程被终止或读回失败，下一次打开只能先核对，不能自动重放。完整只读草稿/当前内容核对后，用户明确采用且新读确认一致，才清理未知状态。已知提交成功但恢复记录清理失败时只重试清理，不重复 SQL。打开草稿也须先确认其身份/基线，不静默把旧草稿覆盖当前内容。损坏日志保留，提供明确删除操作。

普通编辑的恢复快照应合并/串行处理并显示真实草稿写入状态。离开/重载先等当前快照与写入屏障；保存失败不离开。放弃修改先等待旧写入完成，再持久删除恢复记录，防止迟到任务重新创建已放弃草稿。后台或切换账号在退休 WebView 前处理恢复；没有成功持久化时不能显示草稿已保存。保护内容将继续使用现有仅内存原则，不能继承本轮本地正文日志。

## 生命周期与边界

外围页面接共享租约与编辑身份锁，不允许同一数据库记录开两个编辑会话。组件接入可编辑前先绑定生命周期回调。所有加载、快照、保存确认、取消、恢复和异步回调均受当前身份/序列约束；旧页面不会改写新页面。Native close 先退休受控实例，再清 Cookie；保持原有 Cookie 互斥和外链关闭后再启动浏览器规则。脚本异常只显示常量错误，不打印正文。

## 验收

先验证真实 HTML/Univer 点击与键盘修改、公式重算、选中不改原文、未知字段保留和保存确认不抹去后续输入，再覆盖其他四个引擎。SQLite 测试检查真实格式、并发/同时间不同内容冲突、软删除、错误类型、文章重名、原子标签、无修改时间保持及数据库关闭。控制器覆盖持久化失败阻止 SQL、提交丢回调只读核对、清理失败只重试存储、迟到写入/销毁与放弃。

本轮结束仍须冻结源码、分析/回归、只构建 ARM64，在 NAS redroid 用真实输入编辑并保存、导出数据库核对、强制冷启动恢复和清理自有测试夹具，保留原 14 表/2 文档/5 附件。测试环境不放到 NAS 数据备份树，不使用 Win11 模拟器。

### 大文件恢复实现补充（编码前）

20MiB 演示文稿不通过一个巨大加密 SharedPreferences 字符串往返，避免多份 UTF-16/base64/XML 副本。新增仅供 Flutter 调用的原生恢复通道，固定 app 私有目录、SHA256 记录名、AndroidKeyStore AES256-GCM、逐块独立认证（256KiB）、记录头身份/AAD和完整摘要校验。正文记录为有界二进制封套（长度限定的 JSON 元数据 + 原始 UTF-8），不重复转义整个 JSON 原文。文件通过 AtomicFile 回滚/提交与文件/目录 fsync 确认持久化；删除也确认目录落盘。读写/取消串行，读 token/写 token 限额、相同记录互斥，任意路径和任意密钥操作均不开放给 WebView。正文、密钥或原始异常不进日志。损坏/认证失败不返回可用草稿，也不自动删掉原恢复文件。此专用格式不会改变已有 HTML 恢复 preferences/密钥或旧日志。

## 恢复核对页面 v1（实现前设计）
原型：../../prototypes/flutter-rewrite-2026-11-04/29-34-complex-recovery-review-v1.png。
核对页采用白底、深色标题、蓝色分段按钮；先显示上次保存结果待核对提示，再显示当前已保存/本机草稿切换、完整标题与标签、正文/原文切换，底部两项明确选择。正文使用同一真实编辑引擎的只读模式；原文分块显示完整源文档，避免超大单个文本布局。用户必须查看两份内容后才可选择。选择只返回意图，调用方须再次读取并比较当前版本，不能直接重放保存。取消不删除草稿。

本阶段保存锁使用早于引擎监听器安装的输入门禁，覆盖主页面和 PPT 子页。表格实际修改后导出前通过固定版本 Univer facade executeCalculation/onCalculationResultApplied 等待结果；仅对打包适配器应用可复验补丁，上游原文件不变。没有编辑时不引入计算缓存变化。
原生恢复存储在 AtomicFile.finishWrite 后若目录同步或回读失败，保留可能已提交的新记录；没有确认回执则不得开始 SQL。下次打开需只读核对，不自动删除或重试。

### 编辑页并发约束（2026-11-06）
连续实际编辑产生内容 revision 通知，而不是仅干净/脏切换；未改变内容的快照不能递增 revision，避免草稿循环。保存先锁定真实引擎、捕获源、确认普通草稿持久化；关闭生命周期需等待该屏障，然后控制器再将记录升级为 pending 后进入 SQL。屏障失败须等传输操作收尾后尝试最终捕获。离开前不依赖延迟 dirty 通知，必须冻结并读真实快照，再决定是否显示离开确认。恢复核对返回值仅代表用户意图，控制器需重新读取和比较完整基线才采用选择。
当前实现仅本地五种结构化笔记/文章的编辑候选；HTML 完整功能迁移、远程、书籍、分享、受保护文档、附件与导出仍未完成。ARM64 实测前不推广下载包。

## v4 大文件入口与响应式核对（实现前补充）
延续已保存的恢复核对 v1 原型：正常尺寸的颜色、层级、双版本和底部操作保持一致；长标题/最多100个标签或320dp、200%文字时，头部 metadata 区域限制在可用高度的一部分并独立滚动，正文保留有限视口，底部选择始终可达。正在加载或已退休的引擎不启用保存按钮。

旧列表和类型分流不能先 SELECT 整段正文。新增只用于展示的列表 DTO，字段为 id/title/labels/date/preview，preview 在 SQL 返回前截成有界片段；不把 DTO 交给正文保存接口。保留 LocalStore.notes/readNote 默认完整正文契约。编辑入口在同一读取事务先检查 metadata/editor_type，复杂格式直接交给已有分块仓储，不预读正文。Markdown 与搜索需要正文时采用有界 UTF-8 BLOB 分块，BOM/CRLF 不改变。全文关键词查询与 ASCII whole-word 过滤保留原语义，不能只用前缀假装全文命中；结果摘要仅保留150个 Unicode scalar，避免构造整篇 rune 列表。字节超限或损坏只能报错，原库内容不改写。实际20MiB入口/CursorWindow需新ARM64包验证，FFI测试不替代设备证明。

兼容审查补充：Markdown 原有读取/搜索未设20MiB整文档上限，本次保留该契约；null 上限仅用于已确认的 Markdown 路径及书籍正文搜索。固定256KiB分块限制的是单行 CursorWindow 大小。复杂格式编辑仍严格执行各引擎原有5MiB/20MiB上限。书籍正文搜索保持原先排除HTML的条件，不扩展为只允许Markdown类型。
