# 08补充状态：密码解锁与草稿恢复

实现前设计，2026-11-04；继承08 Markdown编辑器原型，补充 `08-unlock.png`、`08-draft-recovery.png`。图片中的示例笔记和时间只用于原型，运行时显示真实内容。

## 解锁

列表点击受保护笔记后显示原生滚动Dialog，最大宽340dp，内部24dp，蓝色锁图标、标题“解锁笔记”、说明、带眼睛开关的密码输入、当前编辑不存密码提示，取消/解锁按钮。触控区至少48dp，随键盘缩放可滚动。提交期间禁重、关闭入口被拦截，错误保留密码并在框下显示；成功关闭并打开编辑器，取消保持列表，不产生空正文编辑器。

接口 POST `/api/blogs/:id/verify-password` JSON password，成功取 blog_content。保存沿用 PUT 的 password 字段，由服务端加密；不得误传 current_password（该字段会触发解除密码），不得把密码写入URL、日志、草稿或持久会话。编辑器关闭即释放密码引用，每次打开重新解锁。其他编辑器类型先分流，不能误当Markdown。

## 草稿

编辑器进入先读取当前文档的草稿；有不同内容则显示“发现未保存草稿”，恢复/使用已保存内容两个纵向全宽按钮，最大宽340dp，左右24dp；对话框滚动适应大字和窄屏。不覆盖已保存正文、不自动把旧草稿推到服务器。恢复后维持“未保存”状态；使用已保存内容才清除该草稿。读取失败显示可重试错误，不装作无草稿；用户未选择前不覆盖历史草稿。

草稿存FlutterSecureStorage，命名空间用local或JSON[规范服务器含路径前缀,服务端member_id]，再按文档ID/新建槽隔离；不能仅按服务器或登录名，也不从未验证JWT中取身份。600ms防抖，后台暂停及时排队写入；串行写/删除，防止迟到写入让已清除草稿复活。成功服务器保存后清除旧草稿；若保存中仍有新输入则保留其最新草稿。所有存储错误保留编辑区内容并提示“草稿未保留”，不能显示虚假成功。

离开未保存编辑器提供保存并返回、保留草稿并返回、放弃修改和取消。保存/草稿写入失败留在原页。受保护笔记不读写磁盘草稿，不提供保留草稿动作，只能保存/放弃/取消，后台暂停不会持久化明文。

## 回归门槛

- 当前服务器协议：正确/错误密码、加密保存仅password字段、取消无PUT、每次重开重新解锁。
- 草稿：跨服务器/账号/文档/新建隔离、重建实例恢复、保护内容拒写、串行写后清除、错误传播、保存中继续输入、选择前不覆盖。
- 原生交互：密码显示开关/禁重/错误重试、恢复/丢弃、离开四个分支、320dp与2倍文本。
- Android安全存储与键盘/后台恢复仍须设备回归；Mock或浏览器截图不能替代真实设备验收。
