# 08 大 Markdown 原文阅读 v1（实现前设计）

原型：../../prototypes/flutter-rewrite-2026-11-04/08-large-markdown-read-v1.png；内置 imagegen 生成，完整提示词为 08-large-markdown-read-v1.prompt.txt。原型先于本阶段实现保存。HTML WebView 原型已单独保存，本次先解决实际设备发现的大 Markdown 阅读卡顿，不把该缺陷标为已通过。

## 触发与边界

既有 NoteEditorPage 的正文保存上限是 UTF-8 500000 字节，本阶段不新增、更改仓库默认全文契约，也不修改这项现有编辑上限。中央 openNativeNoteEditor 在完整读取、类型分流及必要解锁完成后，对既有 Markdown 笔记/文章检查正文 UTF-8 字节数；超过原编辑上限时，打开专用只读原文页面，避免先构建含整篇巨大字符串的原生 TextField。复杂格式继续走各自 WebView 专用路由；普通大小 Markdown 继续走现有原生编辑器。所有调用方仍按 ID 读取完整正文，不用列表 preview 替代正文。

页面只接收读取结果，不接收 repository、save、draft vault、文件写入或网络能力。已解锁保护内容只在本页内存中显示，不能写入草稿。返回无修改、无保存和自动恢复写入。此页不是大 Markdown 完整编辑支持；也不把只读页面伪装成可保存编辑器。

## 布局与交互

遵循已生成原型：白底，深色标题，蓝色只读标签，灰色不可用保存图标，16dp左右边距，10dp圆角细边框。顶部“笔记原文”、返回；状态“只读”，实际 MiB 大小显示为常规 MB 文案，“全文完整保留”；完整笔记标题与标签；浅蓝提示“内容超过编辑上限，已切换为只读原文。”。中文/英文均提供对应文案。标题/标签很长或320dp/200%字体时，metadata最多占可用高度45%，独立滚动；正文仍有有限视口，返回始终可达。

正文按源字符串原样显示 Markdown 标记，不将超长源交给 Markdown renderer 或单个 TextField/TextPainter。每段最多4096个UTF-16 code unit，边界避开有效代理对；正文全部保留，包括 BOM、CRLF、空白与原始顺序。只预先保存小型边界索引，按 ListView.builder 可见项目才创建 substring/SelectableText，不构建整篇 rune List 或所有段的文本布局。各段显示“原文 · 第 x / n 段”和独立细边框；正常滚动可到最后一段，不使用省略号当作全文。蓝色 scrollbar与原型一致。只有返回可操作，不增加尚未实现的导出、复制全部、分享或编辑按钮。

优先抽取已有 ComplexSourceView 的代理对安全分段与 lazy list 为通用 SourceChunks / SourceTextView 组件，使恢复核对继续保留原有默认外观和行为；大笔记页面启用分段标题/卡片式展示。保持原恢复核对的20MiB懒加载与4096边界回归，不能把分段索引变成正文截断。

## 验收

纯数据测试使用超过3MiB、BOM/CRLF/emoji及跨4096代理对的正文，逐段连接必须与原始String/UTF-8完全一致。Widget测试验证少量有界SelectableText、首尾段可滚动到达、保存禁用、返回无平台存储/网络调用、长metadata在320dp/200%可访问。路由测试验证既有超限Markdown走只读页、500000字节及以内仍为原编辑器、普通中文/emoji按实际UTF-8字节判断、未解锁保护内容不先显示原文、复杂类型仍为专用WebView。页面不改写SQL标题、标签、更新时间或附件。

冻结新源码并完成适当分析/回归后，仅用ARM64 APK与NAS redroid验证：用真实完整关键词从3MiB末尾搜索，点击结果成功显示只读原文页、原生UI层级可读取且没有巨大EditableText，滚动与返回正常，冷启动后原笔记与14表/2文档/5附件未改。此前native搜索命中是已通过的事实，打开巨大TextField未通过；新包必须补设备证据。仅有FFI或假platform view不能替代此项。


## v3 交互修订设计（2026-11-07，实现前记录）

v8设备已证明3MiB来源、独立段标题、4096字符节点与真实滚动，但连续拖动默认像素滚动条会出现输入超时ANR。UI层级缺文件只是此前的表象，不能靠重试视为通过。保留v1原型的白底、元信息、原文卡片与右侧8dp蓝色滚动条，修订其定位机制。

蓝色条按原文段号导航：拖动时只预览条的位置，释放后直接将目标段作为滚动锚点；不按整个变高文档的像素距离跨越、排版中间全部段。目标段前后仍可自然连续滚动。使用Flutter已有CustomScrollView中心锚点与前后两条lazy SliverList，不增加第三方依赖，不新增分页按钮或删减正文。段号与标题/正文仍保持独立可访问节点；滚动条提供“原文位置”和按段递增/递减操作。组件只为当前附近可见项创建正文substring/布局，跳到最后一段也不能先构建前面数百段。

plain恢复视图外观和既有行为保持，本次只修订decorated大Markdown原文。新增真实拖动到末段/回首、从目标锚点向前连续滚动、首尾精确正文和少量可见节点测试；实际ARM64需反复首尾拖动、源SHA和完整表/附件不变、进程存活且无本次ANR后，才能验收。保留v7/v8失败证据与未验收标志。
