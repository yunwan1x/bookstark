# Dedicated owned image picker — existing20 UI reused
Use existing20-images.png/20-image-preview.png/20-image-upload.png under docs/prototypes/flutter-rewrite-2026-11-04. No new screen/layout. Existing picker button, upload queue, error panel and leave confirmation remain. Preserve injected pickFiles overrides, other platforms file_selector and existing ShareParams filename overrides.

Actual current Android file_selector allocates byte[provider size] before Dart64MiB validation, copies again into cache with MIME-based extension, and cross_file IO ignores name. New dedicated image-only SAF port preserves normalized original DISPLAY_NAME and provider MIME; original content hash is validated again before actual repository upload. It never changes article imagesOnly5MiB picker or existing attachments APIs.

Native accepts image/png,jpeg,gif,webp,svg+xml; at most20 picks,64MiB/file,256MiB/batch, fixed64KiB copy,120s total copy deadline and128MiB free-space reserve. Provider SIZE and descriptor length rejected before body allocation/copy; unknown/misleading sizes still count every chunk. Atomic selection result: failure/cancel cleans made files; no source or URI becomes an upload entry on partial failure. No persisted URI grants, no external paths, no device Downloads. Only random private inbox IDs cross Dart.

Lifecycle: immutable owner/operation/file IDs; register is awaited before pick, retire waits register then native revoke/copy drain/cleanup. ImageLibraryOwner's awaitable barrier connects to existing Root retireAndDrain before account activation. Cancelled SAF result retains original native slot until original result returns, so next owner cannot inherit it. System SAF handoff alone is permitted; background during copy cancels; activity destroy revokes. Dart epoch/current and native owner checks both apply. No account cookie is passed to provider.

Completed/reused entries and removed entries release private inbox originals; unfinished/unknown entries retain only while page is open to allow explicit retries. Page leave/owner switch retires and cleans all owned originals, not saved library attachments. Root barrier fails closed if native cleanup acknowledgement fails. This does not add cold upload queue recovery or claim hash reuse is the current creation receipt.

Prepared tests use real private files: Unicode mismatched extension/MIME and bytes→actual ImageUploadPayload, release/integrity; held native retirement blocks next scope activation; held SAF response rejected after retirement; same-size tampered original rejected. No Java/Dart/Native execution performed. Actual owned-provider SIZE>64MiB/no-open, filename/MIME multipart, multiple selection, cancel/retire delayed result and inbox cleanup still require the Native SAF successor.
