# 44 迁移候选 schema15 草案
本阶段只构建独立候选数据库的受控DDL与验证，不更改活动LocalStore的schema14或BSTKBK01/schema14备份合同。候选不可被当前LocalStore打开或激活。V3迁移整体原型与V4格式选择原型已先行；此处没有新增页面。

从冻结的createLocalSchema14创建基础，再增加notes.password_hash、is_pinned、pin_order、visibility、legacy_version、create_time；既有内容/标签/ID/时间戳不回写。topic_comments增加parent_comment_id。新字段均有旧记录默认值，迁移不暗自解密或取消保护。

legacy_import_sources记录归档SHA、Go ZIP来源、原manifest和显式格式配方。legacy_import_records以类型/本地ID绑定来源、无歧义JSON元组源键、完整源字段JSON及SHA；书籍/专题的子数组由独立子记录及顺序保存，原归档另行完整留存。legacy_import_label_relations逐行保留全部关系及未知字段，允许重复原关系。legacy_friend_links独立保留所有分组、二维码、描述、排序、开关和重复URL。

所有DDL固定可信，不执行来源SQL；不依赖SQLite JSON扩展，Dart侧负责严格JSON与哈希验证。导入来源只允许go_zip_v1，raw SQLite必须另行显式选择所有者并扩展来源合同。来源SHA、载荷SHA限定小写64位十六进制。本地ID正数，根父评论为0，保护哈希不进入普通列表展示。

暂不添加元数据DELETE触发器：现有专题回收站会物理删除子项，触发器会使原字段无法还原。必须先接通带版本的回收站载荷、恢复和永久清理。活动schema15还需要保护内容的列表/搜索/读取/编辑/加密草稿/后台取消、固定14到15升级及双版本备份验证；这些门槛完成前不改变活动版本、不发布候选、不声称第44组完成。

源字段必须先分类；未知字段仍是阻断项，不得将账号/会话等未知敏感字段直接作为metadata复制。保护格式检查复用实际原生通道同一套Dart边界：bcrypt成本4—14、规范ENC:v1及5MiB正文上限；有ENC但缺原哈希不可解锁，必须阻断。仅结构可支持不代表已验证密码，也不代表来源可信。

## 原字段记录编码（SQL写入前）
逐条生成经过大小限制的metadata JSON及SHA，不一次保留所有编码副本。每条绑定归档、格式配方、类型/新ID、无歧义源键和原数组顺序；书籍/专题头记录子列表是否存在与数量，子项单独保存，避免头记录复制整本文档。字段值、正文、密码哈希与ENC保持原值，不执行解密或编辑器解析；每条UTF8载荷上限32MiB+64KiB，超过明确阻断并保留源文件。

未知字段/未知条目/缺失或不符附件/不支持保护等未解决问题在生成metadata之前阻断。不能以opaque metadata为名复制未知账号/会话字段。已明确选择的编辑器类型和可结构支持的原保护记录可以编码到独立候选，但绝不据此允许当前应用激活。原始归档另行完整保留；已规范化的Go nil空列表不声称能重构原JSON字节。

标签关系单独按原顺序保留，包含新标签/目标ID及原字段，不因目标labels数组需要去重就丢弃原关系。取消在每条编码前后检查，已生成载荷不作为可激活收据，写入者必须在取消/异常时清理自己的独立候选。

## metadata事务与SQLite回读
只接收调用者拥有的全新schema15候选事务，检查版本、外键开关、明确表集合以及全部内容/序列表为空。metadata先写入，随后完整资源写入者再在同一候选流程填充主表。此函数仅写来源、原字段和标签关系三表，不提供激活收据，不把空主表候选作为迁移成功。

来源manifest和显式配方逐字节复核，头部各上限8MiB；每条payload写后按16KiB BLOB分块回读并核对长度/SHA，避免Android CursorWindow整行读取大JSON。进度只包含计数；取消/回调错误/SQLite异常必须传播出外层事务并回滚，SQLite异常不向界面回显SQL参数。源字段不可变，正文/哈希/带凭据URI不进入日志和进度。

## 时间字段转换（主表写入前）
Go models/export.go:parseExportTime使用RFC3339Nano/RFC3339及SQL日期形式；无时区SQL形式由Go time.Parse按UTC解释。新转换也显式UTC，不能受设备时区影响。常用RFC3339偏移与纳秒保留到本地主表毫秒，原始字符串和完整纳秒仍在源字段记录中。毫秒转换必须与Go UnixMilli一致，包括1970年前负时间的向下取整。

严格检查真实日历和时间，拒绝Dart DateTime自动修正非法日期；非空不支持时间明确阻断，不能悄悄改为当前日期。空修改时间依次使用创建时间和归档export_time，确保候选重建确定性。独立Go标准库向量先验收。旧服务器version与本地并发修订不是同一数值，活动schema15读写接线前需单独处理；此工具只转换时间，不生成修订号。

## 原生主表行计划（文件阶段之前）
先生成不可变的SQL行计划并检查目标约束，仍不执行切换。书籍/章节、笔记/文章、书签、任务、专题及子项、标签、友情链接逐类使用已核对的新ID。标签JSON由明确关系构建并去重，原重复关系及book/bookmark旧CSV缓存字段仍在原字段记录中，不拆分缓存字段猜测新关系。

书籍/章节的本地identify使用来源SHA+新ID生成固定ASCII标识，原标识由元组源键保存；跨书籍同章节标识不冲突。旧内容链接需后续来源别名解析，不重写原文。书籍名、文章标题、专题资源目标若触及原生唯一约束，提前阻断，不自动合并/改名。

notes.updated_at及书签整数时间使用Go向量验证的转换；其它TEXT时间逐字保留，后续schema15来源适配器负责正确解释，不能把Go无时区UTC字段当作设备本地时间。原服务器version保存在legacy_version；notes/documents新增正数revision=1，未来CAS及恢复使用独立修订，不以历史负时间或旧int64最大版本作为可递增计数。

除notes.content/documents.markdown外，单行字符串合计上限256KiB，避免整行元数据越过Android CursorWindow。超出明确阻断，无截断。正文原值/密码哈希/ENC原样保留；此计划不证明复杂正文可打开，仍需引擎结构验证及保护读写接线。上传文件/图片、资源别名、脚本资源批准和完整候选验证另行完成，不以主表行数作为迁移完成收据。

## 主表事务写入与逐字段验证
metadata与主表必须使用同一候选事务。主表写入前复核版本、外键、来源及格式配方，并要求原生表均为空；不使用replace/ignore。每个值检查SQLite实际typeof，整数（含int64最大值/负历史时间）按整数核对；字符串以16KiB BLOB分块比较长度和SHA，不整行读取大正文，空串也核对。

主表取消、观察器错误、驱动错误或字节不一致均向外传播，回滚已写metadata及全部资源。对外仅给计数及来源事实；上传仍显式未完成，既不返回切换收据，也不让旧schema14读器打开新候选。
