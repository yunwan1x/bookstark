# 44 旧版迁移：独立 ID 与引用映射
本阶段是已先行 V3/V4 设计下的数据层，没有新增页面。先完成只读身份表，再接候选数据库，不在身份表中执行导入、正文解密、SQL 或激活。

Go ZIP 已通过类型、重复标识、层次循环和引用检查后才能分配身份。每种本地表独立从1分配；原64位整数以十进制字符串保留，绝不经浮点数。身份绑定归档SHA256，只适用于独立空候选，不指向当前用户库。raw SQLite以后必须另加显式选择的所有者范围。

章节使用[书籍标识,章节标识]元组，不用斜杠拼接作为内部键；旧导出的斜杠复合引用可能歧义，遇到多个目标明确拒绝。专题子项的旧ID按专题区分；缺失旧ID的行仍按行位置独立保留，不能丢行或凭空制造可引用旧ID。父评论必须保持在相同专题/目标。

博客统一分配notes表身份，note/article别名分别限定原类型；不推断Markdown。书签URL在目标库受唯一约束，重复源URL必须阻断并进入后续显式冲突处理，不合并、不删除。友情链接允许重复URL，逐行保留。标签、附件使用其经验证原标识。

未知字段和密码/ENC原文仍留在不可变源数据；身份表不复制正文和哈希，不声称迁移已完成。后续候选写入必须同时保存原标识、未知字段、保护数据与全部引用，并完成读写/回收站/备份兼容才能允许激活。

关系计划仅引用同归档身份：章节→书籍/父章节、任务→父任务/专题、摘要/资源/评论→专题、资源→真实目标、评论→摘要/资源/任务及父评论、标签→资源。专题子项先分配全部身份再解析前向引用；缺失原ID的行可保留但不可被凭空引用。计划不可变，保留重复标签关系，仍不写SQL或激活。

格式配方接线从真实检查结果重建格式来源，再用严格反序列化验证归档SHA、全部博客标识和七种显式格式；不信任另一个页面对象附带的正文/标题/哈希。已知章节doc_type严格识别，不推断excalidraw等未知别名，未知类型阻断。仅消除已由选择解决的editorTypeMissing，其余保护/未知字段/缺失附件问题保留，映射不成为候选可激活声明。
