# Owned complex resources v1
Prototype: owned-complex-images-v1.png, builtin image_gen; generated and inspected before implementation.
Scope: authenticated existing remote notes and book documents using real packaged engines. Protected memory-only editors may inject the same capability; no decrypted body/password enters an ordinary disk draft. Existing article source-IO work remains separate.

## Verified existing wire
- routers/router.go:182 GET /upload-files/*filepath calls controllers.ServeUploadFile. upload.go:34–65 explicitly serves public files with no auth. These are NOT private per-account files. No private-file endpoint will be invented.
- routers/router.go:430 POST /api/uploads is auth/CSRF guarded. UploadImage accepts multipart file and category. It sniffs MIME, enforces server max size, hashes/deduplicates, encodes images, stores a media row, and returns code0/data{id,url,thumb_url,file_name,width,height,file_size}. Upload reply has no member_id/hash/category/MIME: do not claim ownership from absent fields.
- GET /api/uploads/by-hash/:hash is authenticated but returns a global matching image, not evidence this action uploaded it. Read-only manual association must stay distinct from a positive POST receipt.
- All URLs are server-root /upload-files aliases and must resolve beneath the configured server path prefix. Deny userinfo/query/fragment, traversal/double-encoded separators, other origins/ports, arbitrary API URLs and redirect targets.
- Current owned complex route passes no resource broker. Native denies nonasset URLs and all HTML file-chooser operations; shared/public resources cannot be borrowed as an account owner.

## User interaction
Existing editor header gains a single image attachment action only when a real engine insertion adapter supports this kind. It opens the actual system SAF picker; temporary picker background does not retire the live account owner. A file selection alone neither uploads nor changes the document. Validate bytes/MIME/dimensions, show thumbnail/name/size and an initially unchecked explicit confirmation. Cancel keeps complete current draft and sends zero POST.
Upload and insert prepares multipart and legal CSRF first, then durably marks the upload attempt immediately before the one actual authenticated upload. Explicit consent is bound to the selected exact byte hash and owner/document/runtime snapshot. A synchronous beforeSubmit rechecks current account revision, owner lease, file hash and abort.
Positive validated upload receipt permits exactly one explicit engine image command; it does not save the document. Capture actual engine source after insertion and persist through the existing controller/vault; ordinary Save retains same resource ID/full-fingerprint/body-only CAS.
Uncertain upload returns the separate review state in the prototype. It never auto-reuploads, never inserts a guessed URL, and never claims a created resource. Read-only matching/media review may manually select an existing exact reference; it is labeled adopted existing. Back returns to the unchanged editor. A durable unknown attempt blocks repeated upload of that attempt after cold reopen.
Known uploaded ID plus insertion/checkpoint failure retries only insertion/storage with fresh runtime checks, never POST. Failure during unknown/retirement preserves the prior complete source and recovery metadata. No automatic delete of a possibly shared/deduplicated uploaded image.
English and Chinese use equivalent explicit wording. The confirmation and unknown state scroll vertically, actions wrap/stack, and 320dp/font2/180px IME remain reachable.

## Capability split
OwnedComplexResourceLease captures client reference, memberId, sessionRevision/token identity, server origin/prefix, namespace, note/bookId/resourceId/kind, source fingerprint, runtime lease and generation. It has current/retire/abort and separately tracked real requests/jobs. It never grants URLs based solely on a source-provided field.
GET is restricted to an immutable canonical allowlist extracted from the current verified document exact source; a validated positive upload receipt plus explicit insert may extend it with that exact URL. Same-origin arbitrary upload paths are still denied. GET resource policy uses a dedicated no-cookie HTTP sender for the actual public /upload-files and limited /static assets. Limit 5MiB/object, 20MiB/document, 32 distinct resources, 4 concurrent, 15s absolute deadline including queue/body/decode; reject redirects/HTTP errors/unsupported MIME and decoded image size over 16M pixels/8192 edge. Static permits only image/font/CSS, never JS/HTML/API. Account/session checks bind lifetime even though file GET is anonymous under today's Go protocol. Public/shared existing policies stay separate.
Native sends resource URI + runtime lease only to the Dart broker, never account cookies/token/password into DOM/boot/messages. The native asset policy allows exactly broker-owned references plus existing package assets; it does not permit general fetch/XHR/network or account file URLs.
For protected memory routes, capability stores identity hashes/upload-attempt metadata only via its explicit memory-only retention contract; it does not serialize decrypted source or password. Server upload is a separate user-confirmed disclosure.

## Real engine insertion audit and staged acceptance
Richdoc has actual instance.command('executeImage',{value:url,width,height}) used by existing richdoc-editor.js:1839; use it with actual live selection/range validation.
HTML uses the existing CodeMirror replaceSelection path for a quoted img element at the actual selection, not source string concatenation. Source remains exact except that explicit insertion.
Other engines need their genuine exposed API traced before claiming support. No raw JSON rewrite or fake dispatch success for spreadsheet/drawing/mindmap/PPT. An unsupported kind may read existing allowed resources, but its insert control stays disabled with an honest message until its real adapter is implemented and validated.
Before acceptance: bounded byte/MIME/Unicode/prefix/redirect/private-header/late-reply tests, mocked actual HTTP CSRF/retirement zero POST and unknown no retry, genuine engine host contracts, widget picker/cancel/large-font cases, then fresh ARM64/redroid engine-image rendering/upload/explicit Save/cold/source CAS/owner switch tests with exact original restore. No executed validation claimed by this design.
