# 37 用户详情、审批与密码重置：实现前设计
2026-11-07。原型为虚构账户，仅设计，不代表实现或实际回归。完整API契约见相邻 admin37-contract.md。
## 页面与交互
详情显示列表实际可用字段：账号、ID、角色、审批、注册与最后登录时间；不显示列表未查询的邮箱。操作前重新读取所属页，匹配ID并核对状态，无法找到时停下，不能把旧快照当实时详情。
审批处理先选择通过或拒绝，再打开明确目标及新状态的确认；拒绝确认沿用原型中审批确认布局、文字改为拒绝，颜色辅助但文字必须明确。请求处理中禁止连点。成功后重新GET核对；不存在的审批目标后端也可能返回成功，所以找不到不显示已核对成功。读取变化不能证明本次写入。
密码页只用于已通过成员；遮蔽的两次输入必须一致，UTF8编码长度6–72字节，客户端不持久化、不打印密码。提交前有目标确认；成功清空输入并显示回执，未知结果清空密码并禁用旧提交，不自动重试。原型右图下方未知结果卡是替代状态，不能与可提交表单同时启用。
操作中退出后迟到结果不能更新其他账户页面，401/403清除资料与表单。角色操作仍需独立原型，本文不授权无设计直接实现角色界面。
## 样式与可访问性
白底、深蓝正文、蓝色主按钮、圆角卡片、16dp边距、至少48dp触控目标。320dp和200%字体时卡片/确认框滚动自适应，不固定图片高度，不截断账号。状态同时带文字。原型全部示例日期与账号不可硬编码到产品。
## 测试计划
验证审批确认取消无请求、精确ID/method/body、成功后回读、未知不重试、不存在ID回读缺失、旧会话丢弃、401/403清除。密码验证UTF8边界及不一致、遮蔽、成功清空、transport未知且无自动重放。隔离Go与NAS redroid实际操作独立核对，禁止生产密码/邮件/用户变更。
