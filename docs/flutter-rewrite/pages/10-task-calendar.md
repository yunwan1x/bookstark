# 10 待办日历补充设计（实现前）

原型 `10-task-calendar.png`，内置imagegen，提示词同名prompt.txt。原生返回/待办日历，统计说明，白色边框月份卡（月份前后切换、周一至周日七列、正确星期偏移、选择日蓝圆），数目来自真实daily-counts；下方选择日修改记录列表与清除日期筛选。周列不按文本总宽硬排，Grid每格可触控；小屏/大字日历与结果整体滚动。

- 月份初始为当前本地日历月份；原型2026-11-04仅视觉样例。切月从真实API获取该月count/done_count/active_count，有单独加载/错误/重试，不把失败画成零。旧月份慢响应不得覆盖新月份。
- 周一首列，星期偏移=(monthFirst.weekday-1)，DateTime(year,month+1,0)计算真实天数；含闰年与跨年、七列和六行容纳的月份。图中2026年11月1日为周日。
- 数字代表修改日的全部状态总量，不随未完成/已完成筛选伪造服务端分母；可用实际active/done作说明。蓝圆是所选日期，不把“今天”与“已选择”混同。
- 点击日使用date参数筛选任务，标题“X月X日·修改记录”。保留真实截止日期标签：同日修改的任务可以截止在另一日期。截止筛选和修改日筛选有各自状态，清除修改日不改任务本身。
- 数字日期使用纯日历字符串比较，不能先把Go带时区时间转成本机时区再改变服务端substr(modify_time)分组。月份翻页不执行任何任务写请求。
- 结果使用与列表同一个TaskCard/完成锁/原生编辑与子列表，不另造不可交互的静态卡。日期结果分页读取真实total，不能只展示日历数字对应前30条便宣称全部。
- 无记录时给出该日空状态；后台修改或完成任务后同时刷新所选日结果与当前月计数；显示重试不清除已加载任务和用户输入。

需验证闰年/跨年/首尾空格、服务端计数语义、筛选/分页/竞态、中文英文与200%字体、截图和Android实际回退。此图和编辑图不代表任务页面实现完成。
