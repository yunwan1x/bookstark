沿用总览白底、深蓝字、蓝色动作、浅蓝12dp分区卡片、16dp边距、48dp目标。390dp主机表单顺序是连接信息、登录凭据、高级设置和明确保存。名称、地址必填；端口默认22且1–65535，Shell默认/bin/sh；高级区保留工作目录和绝对Docker Socket路径，禁止换行。320dp或200%字体改为单列，各区和底部动作可滚动，字段使用稳定key，错误条移除不能丢焦点。保存不会自动执行连接测试。

主机选择真实已有凭据ID；用户名/认证类型从选中元数据只读展示。新增凭据是独立路由，只有收到创建回执并重新读取到真实ID才能选用；未知创建不得重试POST或凭名称自动认领。保存主机 POST/PUT /api/admin/assets/ssh-hosts[/id]，完整保留shell/cwd/docker_socket_path及选中的credential_id，不把列表返回的明文凭据重新送回服务器。编辑原有主机仍需先明确选择/保留其真实凭据；旧credential_id=0兼容路径需独立验证，不能静默丢掉内联凭据或创建新凭据。

Go UpdateAssetSSHHost 在 credential_id>0 时选择已有凭据；在提供非空内联credential而existingCredentialID>0时，会直接修改该共用凭据。客户端不在主机表单内暗中走后一种行为，凭据修改单独进入受限编辑。主机删除不会自动删除其凭据；新增凭据后放弃主机也不能自动删除凭据，已产生的独立资源要如实说明。后续隔离Go实测需覆盖部分创建、共享引用和删除约束。

凭据新增/编辑 POST /credentials 与 PUT /credentials/:id：名称、用户名trim后必填，认证方式password/key。密码/私钥字节原样传输（Go只用TrimSpace判断空，不trim实际秘密）；新建必须非空。编辑默认空的新秘密输入表示保留原值，绝不以掩码圆点作为字段值。更新认证类型而不提供新秘密会让Go保留旧密文但更改类型，表单需要要求类型变化时提供相应新秘密。修改凭据可能影响SSH与WebDAV的其他引用，保存确认必须明确这一影响。

图中“更新密码”卡片的圆点仅表示用户已新输入的掩码示例，真实初次打开编辑必须为空并显示“留空保留原值”；不预填从列表收到的秘密。key模式用可滚动多行掩码字段，默认掩码、显式查看动作，离开/后台/失权/注销/换空间清除引用并恢复掩码；不持久化到普通草稿、日志或截图。明确查看既存秘密的路由与设计还需单独补齐，不能拿新输入的眼睛按钮替代。
