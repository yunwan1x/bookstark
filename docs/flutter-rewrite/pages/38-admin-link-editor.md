# 38 友情链接编辑：实现前设计

2026-11-07。内置 imagegen 生成的 38-admin-link-editor-v1.png 已先于实现保存；全部示例为虚构，不代表实际配置。原型为普通链接与二维码条目两种编辑状态。

390×844逻辑尺寸，白色标题栏、深蓝文字、蓝色主按钮、浅蓝12dp圆角卡片、16dp边距。字段说明在输入框外。底部“应用到草稿”只修改所属列表的内存草稿；返回列表后由“保存全部链接”明确发起整表PUT。取消、返回或放弃不能隐式写入服务器。新增/编辑共享表单，明确新增状态；名称/地址/分组/顺序/启用/描述/二维码字段都保留，不因当前滚动区域不可见而丢失。

二维码状态仍保留可选链接地址、分组顺序与组内排序，放在滚动区续页；原型右图只展示首屏。既有非空链接地址不能因二维码模式隐藏而清空。二维码只能使用规范的本站 /upload-files/ 图片路径，图中缩略图只是占位；实现预览时必须复用受限同源附件读取，不能直接抓取任意远程图片。图片加载失败只显示失败状态，不阻止保留有效路径。切换类型不能静默丢弃字段。

按现有Go字段语义处理：名称/分组100、URL/二维码2048、描述1000 UTF8字节；普通链接要求HTTP(S)地址，二维码允许无链接地址。服务端会修剪字符串，启用值规范为0/1；提交前可以提示规范化，但不能把旧值偷偷删掉。二维码同一分组的标题和描述必须一致，最终在完整列表保存前检查跨条目约束；单条表单不能声称服务器已批准。

页内删除仅移除草稿，需目标确认；整表保存、清空、并发覆盖和永久删除评论使用另一份确认原型。未保存退出需要明确继续/放弃；保存期间冻结字段与重复操作。401/403、空间切换和注销清理所有所属草稿、二维码读取及迟到回调，不记日志、不持久化服务配置。未知PUT结果只允许先读取核对，不自动重发。

320dp/200%字号改为单列排序字段，标题和警告完整换行，表单可滚动且键盘不遮唯一提交入口。后续必须覆盖UTF8边界、未编辑字段保留、QR路径与分组约束、确认取消零请求、所有权撤销、整表重建ID/服务端规范化与未知结果。NAS redroid仅运行ARM64候选并独立SQL核对；本设计不构成第38组验收。
