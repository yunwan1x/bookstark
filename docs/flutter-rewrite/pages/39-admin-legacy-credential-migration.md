迁移必须fresh同一session/owner/role0，并重新读取完整主机与凭据列表，核对真实host ID、旧式状态和所有已展示元数据。只从明确目标的最新原始响应中短暂取秘密，其他明文立即丢弃引用；不写磁盘/日志/截图。不能拿元数据“未提供”推定为空。目标未提供可用秘密时，不创造空凭据；提供绑定现有/明确新建/取消，禁止自动删除旧主机。

先POST创建独立凭据，传原始秘密字节（密码首尾空白/私钥换行不改写）；实际提交后清理秘密引用，只保留本scope内不可导出的随机HMAC核对对象及元数据。第一步有合法成功回执和真实正ID、响应与fresh GET按该ID核对一致后，才可进入第二步。不得按同名记录猜ID，未知创建不自动重发，也不能继续绑定未确认记录。

第二步前重新核验owner、原主机未变化且仍是旧式、已确认的新凭据ID及元数据未变化，再PUT完整已核对主机字段，credential_id为真实新ID，无credential字段，不隐式修改共用凭据。成功后分别读取主机绑定和独立凭据当前资料。若并发修改、角色/会话变化或目标删除，停止，不覆盖别人的主机修改。

两步不是服务器原子事务。第一步已确认但第二步未提交/被拒/结果未知时，明确显示“凭据已创建（ID），主机绑定未确认”及真实当前资料；不自动删除新凭据，也不自动回滚主机或重试PUT。重新读取只能核对，不能证明未知请求。用户可明确结束核对/返回真实凭据列表。后续重新迁移必须从当前状态重新开始，不能悄悄重复创建。关闭/后台/失权清理全部秘密及旧响应，不能因迟到回执在新owner继续第二步。

更换或关闭资产加密前，除设置新鲜核验外，还需fresh读取全部主机/凭据元数据；只要存在旧式ID0或引用不到真实凭据ID的主机，就先要求迁移/明确绑定，不发设置PUT。读取失败也不能假设没有旧式记录。保持当前密钥、只修改终端策略不触发重新加密，可使用最新真实密钥保持原值，不被误判为空而关闭。这个保护不是给服务器补CAS，预读后仍可能有并发新增旧式记录；明确提示并发限制，最终服务端未提供原子迁移接口。
