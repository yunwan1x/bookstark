# 09 文章列表与编辑：实现前设计

原型为 `09-articles.png`，内置 imagegen 生成，原始提示词 `09-articles.prompt.txt`。沿用 AppTheme 的 Slate、主蓝、白底、8dp 圆角。390×844 逻辑尺寸：56dp原生AppBar，左右16dp，搜索与筛选行，标题/说明，白色带边框文章卡片，右下角新建。列表卡标题14sp/600、摘要14sp最多两行、标签11sp、更新时间次要色。320dp和英文/200%字体必须可换行，不固定卡片高度。

## 交互和契约

- 本地/服务器首页均有文章入口。文章是独立类型 `article`；不把所有笔记改成文章，不混用新建草稿。
- GET `/api/blogs?type=article&page=N&keyword=...&label=...&pinned=...`，完整跨页筛选由后端完成。服务端原有顺序是置顶优先、pin_order、modify_time倒序；原型“最近更新”菜单保留此顺序，另外提供“仅置顶/排除置顶”，不假称支持服务器不存在的任意排序。
- 标签筛选弹窗输入准确标签名，可清除；也可点行标签筛选。按服务端实际 labels 显示，空白状态区分无内容/筛选无结果。
- 选择模式只针对已加载记录，显示选中数，支持全选当前已加载项/取消，批量移回收站必须确认。逐项提交，部分失败保留失败项与原因，不能宣称全部成功。加载/提交禁重复操作，切筛选清空选择；回收站还原在28页实现。
- 行菜单编辑/移回收站；保护文章走同一密码解锁和保护保存。非Markdown类型不能送入Markdown编辑器，后续对应29—34原生编辑器接续；未完成时明确提示，不能写坏原内容。
- 编辑直接复用08组件：原生Markdown/附件/安全草稿/脏内容离开；标题、未命名默认值、恢复与加密提示采用文章文案。新建 POST `/api/blogs` 明确blog_type=article/editor_type=markdown/visibility=0；更新不改原有可见性/类型/保护设置。文章同名后端409保持输入和草稿，不能产生重复新建。
- NoteDTO保留真实更新时间与标签；读详情再编辑，不把列表摘要写回正文。文章新建草稿使用独立命名空间，旧笔记草稿键保持不变。
- 本地SQLite升级到v3，新增collection，既有v1/v2记录默认note。读写/删除受collection限制，note/article均存原表并保留ID，全局附件目录不重复复制。升级只操作新Flutter数据库，不碰旧Android库。集合值限定note/article，查询参数化。
- 错误/重试/加载/空白/英文均真实，禁止生产fixture数据。

## 验证与未完成边界

须有v1/v2→v3升级、文章笔记隔离（含误用ID）、分页标签筛选、批量部分失败保留、草稿命名空间、真实服务器类型/保护保存、320dp英文大字、原型/实际截图和APK。复杂编辑器、发布/分享/导入、真机迁移是全量目标中的其他闭环，不以基础文章CRUD代替全部验收。
