评审日期：2026-07-17

## 本轮整改

- 将连接、标注、聊天和会议中的共享文档、摄像头、聊天浮层拆成确定性媒体 fixture；只固定媒体内容，导航、任务面板、工具栏、状态栏和交互控件仍由真实 DOM/CSS 渲染，没有使用整张原型截图覆盖页面。
- 工作区网格由错误的 `8px` 密集点阵改为与原型一致的 `16px` 点阵和 `136px` 主网格；连接状态 SSIM 从 `0.7134` 提升到 `0.8695`。
- 11 个状态使用独立、固定视口基线；移动连接、移动标注、移动聊天和移动横屏不再复用桌面缩放布局。
- 20 个确定性 fixture 已无损转为 WebP 并内联，最终 HTML 不再引用外部 `webrtc-fixtures/` 路径。
- 桌面壳层统一为一级导航、任务面板、顶栏工具、工作区和状态栏的共享坐标系统。
- 连接、标注、聊天、会议、设置、介绍、活动 7 个桌面状态重新按原型组织内容密度和控件层级。
- 会议 fixture 改为 5 路摄像头和独立布局编辑状态；标注 fixture 补齐作者筛选、图形/演示工具、三列样式和历史操作。
- 移动连接使用 `941x1672` 原稿尺寸；移动标注和聊天从双机原稿分别裁取基准；横屏使用 `1672x941` 原稿，并增加 `932x430` 等比缩放回归。
- 固定媒体 fixture 直接内联确认原型中的人物画面，不再用渐变头像占位。当前指标为全图比对，没有使用媒体 mask 放宽结果。
- 修复小屏状态栏继承旧 fixed 定位导致的底部空白和内容遮挡。

## 评审方法

- 基准：`docs/webrtc-prototypes/` 的 10 张确认原型。
- 工具：`tmp/webrtc-redesign-pixel-qa.ts` 和 `tmp/webrtc-redesign-pixel-metrics.py`。
- 每个状态输出 `reference / actual / absolute diff / overlay / board`，并将指标和实际几何写入 `tmp/webrtc-redesign-pixel-report.json`。
- 全状态联系板：`tmp/webrtc-redesign-all-states-review-board.png`。
- 指标：SSIM 越高越接近；归一化 RMSE、显著像素差率越低越接近。
- 验收门槛：非媒体区域 SSIM 不低于 `0.97`，显著像素差不高于 `3%`。当前全图未做 mask，因此结果更严格，但与门槛仍有明显距离。

## Design Review 结论

已修复的 P1/P2 问题：

- 桌面任务区与画布比例失衡、状态栏和顶栏不共用基线。
- 标注工具数量不足、样式控制缺失、会议摄像头数量和布局错误。
- 设置/活动工作区错误显示网格背景。
- 移动连接未按原稿尺寸实现；移动标注/聊天底栏提前悬浮并遮挡正文。
- `932x430` 横屏直接使用固定坐标导致工具越界。

当前未发现页面错误、外层滚动、控件越界或过小触控目标；但这只证明结构和可用性合格，不能替代像素指标。

仍然明显的视觉差异：

- 原型为生成式高保真产品图，字体抗锯齿、图标形态、共享文档细节和摄影素材处理与浏览器实现仍有系统差异。
- 会议状态的摄像头构图、共享文档内标注和左侧源列表细节差异最大。
- 移动 07 原图同时包含两台带外部留白和阴影的设备，独立裁图后设备轮廓、面板纵向密度和文字渲染仍偏差较大。
- 多个状态的字号、图标笔画、局部留白和小控件边界尚未达到 2px/3px 级别。
