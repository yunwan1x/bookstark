# 工具包格式与发布

多文件 Web 应用可以直接上传 ZIP，作为工具发布，不需要先创建文章。文章发布仍然可用，两种来源共用名称、图标、分类、权限、可见范围、审核、安装和更新流程。桥接 API 见 [插件开发指南](plugin-development.md)。

## 最小工具包

将工具的构建文件放到 ZIP 中，至少包含一个 `.html` 或 `.htm` 入口：

```text
my-tool.zip
├── tool.json                 # 可选，预填发布设置
├── index.html
├── assets/
│   ├── app.js
│   ├── app.css
│   └── protocol.wasm
├── workers/
│   └── session.js
└── data/
    └── dictionary.json
```

压缩的是构建目录内的文件。入口可以位于子目录，如 `app/index.html`，但需要在配置或检查页选择正确的入口。没有配置时，优先识别根目录 `index.html`，否则选择按名称排序的 HTML 候选；继续前请在页面确认。

安装器保存包内全部文件，不依赖 HTML 静态引用来判断哪些文件需要下载。动态加载的 WASM、Worker、字典和其他文件也必须放入包内。相对目录保持不变；指向实际包内文件的根路径引用会在安装时调整。外部服务或媒体直播仍是联网请求，不会因为上传 ZIP 就变成离线资源。

## 可选的 tool.json

`tool.json` 位于压缩包根目录，使用 UTF-8 JSON，最大 16 KiB：

```json
{
  "title": "文本工作台",
  "description": "保存输入状态，读写工具自己的文本文件",
  "version": "1.0.0",
  "entry": "index.html",
  "category": "document",
  "access": "public",
  "permissions": {
    "schema": 1,
    "read_files": true,
    "save_files": true,
    "socket_tcp": false
  },
  "notes": "首次发布"
}
```

| 字段 | 含义 |
| --- | --- |
| `title` | 工具名称，可在发布设置修改 |
| `description` | 工具简介 |
| `version` | 不可重复的语义化版本号，如 `1.0.0`、`1.0.1` |
| `entry` | 包内 HTML / HTM 入口的相对路径，必须存在 |
| `category` | `document`、`image`、`media`、`development`、`productivity` 或 `other` |
| `access` | `public`、`login`、`members` 或 `inherit`，仍受市场设置约束；指定成员在发布表单中选择 |
| `permissions` | 仅需声明 `schema: 1` 与 `read_files`、`save_files`、`socket_tcp` 三项平台权限；浏览器能力默认允许，见 [权限说明](plugin-development.md#43-平台权限与浏览器默认能力) |
| `notes` | 本版本更新说明 |

不提供 `tool.json` 也可以发布：上传后选择入口，再手动填写发布设置。提供配置时，格式错误或指定不存在的入口会让检查失败。权限配置只声明工具需要的能力，不能绕过浏览器授权或服务器 TCP 代理开关。

## 上传和发布

1. 在「广场 → 工具」点击排序右侧加号，进入独立「发布工具」页。
2. 切换「上传工具包」，拖拽 ZIP 或选择文件。上传过程中显示进度，可以取消。
3. 上传完成后等待解包检查。检查页显示压缩包大小、解压后大小、文件数量、可滚动的路径清单和入口选择；失败时显示原因，可重新上传。
4. 点击「下一步」确认工具名称、版本、分类、图标、权限和安装范围。检查页通过不等于已经发布。
5. 发布或提交审核。管理员直接上架；普通成员是否需要审核，由市场设置决定。
6. 在实际安装工作区中安装并打开，检查动态资源、刷新、保存数据和错误处理。

上传页的「我的工具包」可重新进入当前账号的上传记录。发布表单的「保存草稿」保存在当前浏览器会话，不会直接上架。

## 更新同一个工具

进入原工具的发布设置，点击「更换工具包」，上传新 ZIP。工具 ID 不变，已有安装可以发现更新。新的 `tool.json` 可以填写新版本和权限；发布页提示权限变化，用户安装新增 BookStark 桥接权限的版本仍须确认。

版本号不能覆盖。工具包完整清单与每个文件的大小、摘要随版本校验，文件缺失或字节被修改会使检查或安装失败。更新准备成功后才替换当前安装；失败保留旧安装。代码和静态资源与运行数据分开，既有安装实例、localStorage 状态及通过文件桥接保存的用户文件继续保留。

被替换且不再被任何工具或版本引用的上传，超过 24 小时后，会在该账号后续上传时回收。当前可继续发布的上传、待审核及历史版本引用的资源保留；这不是固定在上传满 24 小时后执行的定时删除。

## 导出已安装工具

ZIP 来源的工具安装后，可在独立运行页右上角「更多 → 导出工具包」下载程序 ZIP；文章来源的安装不显示这个入口。导出包含当前程序的 HTML 入口、完整静态资源和重新生成的 `tool.json`，保留名称、版本、分类、图标及权限，并将安装专属资源路径转换为可移植的包内引用。

程序包不包含 localStorage、工具生成的用户文件、安装实例信息或市场凭据。「导出数据」仍单独下载使用状态 JSON。导出的安装范围默认设为 `login`，不迁移原指定成员名单；重新上传后应在发布设置确认权限与安装范围。再次上传该 ZIP 仍走检查、发布及登录安装流程，不会恢复旧会话或自动复制原实例的使用数据。

只有登录账号自己的安装可导出，并同时校验当前修订号与安装实例。更新改变修订号，卸载会使安装失效，因此旧导出请求会失败；导出 ZIP 仍受下述大小与文件数量限制。生成的 `tool.json` 也计入 256 个文件，因此原包没有配置文件且已经占满 256 个资源时，无法再导出为这个格式。

## 限制与运行条件

| 项目 | 上限或要求 |
| --- | --- |
| ZIP 文件 | 64 MiB |
| 解压后总量 | 256 MiB |
| 单文件 | 64 MiB |
| 文件数 | 256，包含 `tool.json` 等包内文件 |
| HTML 入口 | 发布时不超过 20 MiB |
| 配额 | 还受安装或上传工作区 WebDAV 单文件和总配额限制 |
| 路径 | 必须是安全相对路径；拒绝绝对路径、穿越路径、反斜杠、符号链接及重复路径 |

专用 Worker 可用于后台计算和 WASM 执行，网络访问仍受工具权限控制。`BookStark` 桥接对象注入到工具页面，Worker 需要通过消息与页面协作，不会自动获得这个对象。Service Worker 注册被禁止，插件应由 BookStark 管理安装与版本。

WASM 文件能随包分发，不表示任意桌面软件能直接运行。程序及依赖必须适配浏览器 WASM，系统 socket、文件、进程和原生动态库等调用仍需要替换或桥接。多线程、图形加速和设备 API 还依赖实际浏览器及运行环境。

## 存储和下载

工具身份在 `md_tools` 中保存，来源为文章或工具包。旧文章工具升级时保留原工具 ID、版本记录和安装关系，不重新创建安装或搬动用户数据。

上传记录与文件清单存储在 `md_tool_packages`；解压后的资源保存在上传账号的内置 WebDAV `/BookStark/tool-packages/<上传标识>/`。ZIP 作为导入格式，不作为数据库中的二进制发布包长期保存。客户端安装后仍使用独立安装资源目录，用户运行数据使用自己的数据目录。

跨市场安装按完整清单下载资源，绑定上传标识和版本，并检查当前与该历史版本的访问规则。市场会话只发送给明确配置的同源包资源接口，不发送给任意外部依赖或重定向地址。下架后停止新的下载，已经安装的副本仍可使用。

## 发布接口

普通使用优先通过页面操作。需要接入自动构建上传时，可使用以下接口；写请求仍须通过工作区认证和相应 CSRF 或 API Token 校验：

| 接口 | 用途 |
| --- | --- |
| `POST /api/tool-packages` | multipart 上传，字段为 `file`；更新已有工具时另传 `tool_id`。返回工具 ID、上传标识、文件清单及入口候选 |
| `GET /api/tool-packages/:token` | 所属账号或管理员读取上传检查信息 |
| `GET /api/tool-publications` | 列出当前账号的工具包发布记录 |
| `GET /api/tool-publications/:id` | 读取共用发布信息；指定待发布包时使用 `package` 查询参数 |
| `POST /api/tool-publications/:id` | 提交发布设置；工具包来源需包含 `package` 上传标识和 `entry`。`preview=1` 只检查，不新增版本 |
| `DELETE /api/tool-publications/:id` | 下架工具并撤回待审核版本，保留历史与已安装副本 |
| `GET /api/tool-package-assets/:token/*filepath?revision=…` | 下载指定已发布版本的原始包文件；市场访问规则和历史版本规则同时生效 |
| `GET /api/tool-installs/:id/export?revision=…&instance=…` | 导出当前账号的 ZIP 来源安装；两个查询参数使用安装记录中的修订号和实例，成功返回 ZIP 附件，不返回运行数据 |

原文章发布接口 `/api/blogs/:id/tool` 继续保留；其中 `id` 是文章 ID。共用发布接口中的 `id` 是工具 ID，二者不应混用。
