# Airdrop HTML 核心场景回归测试计划

适用对象：分享页“airdrop文件分享助手”及本地独立文件 `tmp/share-1783432865442847645.html`。

修改该 HTML 时，必须按改动影响范围回归本计划。若新增或调整房间、连接、传输、音视频或缓存主流程，先更新本文档。

## 测试环境

- 使用至少两个独立浏览器上下文模拟多台设备；多设备广播使用三个页面验证。
- 自动房间测试连接实际 WebSocket 信令服务；必要时使用本地信令服务隔离线上状态。
- 音视频自动化使用 Chromium fake media，真实权限和移动端行为至少人工验证一次。
- 测试前后记录控制台错误、未处理 Promise rejection 和 PeerConnection 状态。

## 核心场景

### 1. 房间与设备连接

- 创建房间、复制房间号和邀请链接正常。
- 第二台设备输入房间号后加入，双方显示设备且 DataChannel 可用。
- 第三台设备加入后，各 Peer 独立连接，设备数量和选择状态正确。
- 某台设备离开只清理对应连接，房间内其他设备继续可用。
- 房间不存在、信令断开、STUN 配置错误和 P2P 失败均有明确提示及重试入口。
- 在线邀请面板提供 `复制房间号` 和唯一的 `复制邀请链接` 操作；邀请链接携带单个规范化 `room` 参数，打开后自动进入对应房间。
- 本地 `file://` 模式不复制不可访问的本地链接，邀请链接按钮禁用并提示改用房间号。

### 2. 文件传输

- 单文件发送、接收、进度、完成和下载正常。
- 大文件分片、暂停/失败处理和 DataChannel 背压不阻塞界面。
- 多设备存在时，文件分别发送给所有明确选中的目标设备，未选设备不能收到文件。
- 每个接收端有独立传输任务、进度和结果；一个接收端拒绝或中途离开时，其他接收端继续传输。
- 文件发送开始后修改设备选择，不改变已经开始任务的目标快照。

### 3. 文字与链接传输

- Enter/按钮发送、长文本、链接和特殊字符显示正确。
- 多设备存在时，文字分别发送给所有明确选中的设备，未选设备不能收到消息。
- 文字发送结果能区分全部成功、部分成功和全部失败。
- 收到/全部筛选、时间线顺序和未读状态正确。

### 4. 摄像头与麦克风

- 权限允许、拒绝、设备缺失和轨道意外结束均正确处理。
- 摄像头与麦克风可以分别开关，远端状态同步准确。
- 未选择目标设备时不能开始音视频分享，并明确提示先选择设备。
- 只选择一个设备时，仅该设备收到持续音视频，其他在线设备不能收到媒体轨道。
- 多选接收设备后，所有已选设备同时收到持续音视频；单个 Peer 失败不影响其他接收端。
- 分享期间新设备加入后只进入可选列表，默认不接收；手动选择后才添加媒体轨道并协商。
- 分享期间取消某台设备的选择后，仅该设备停止接收，其他已选设备继续播放。
- 分享状态区显示实际接收设备名称以及逐设备的协商中、直播中或发送失败状态。
- 取消最后一台接收设备时出现停止确认；确认后停止全部分享并释放摄像头、麦克风轨道。
- 先选中新设备再取消旧设备时，本地媒体采集不中断，不重复请求浏览器权限。
- `停止全部分享` 后所有 Peer 的媒体 sender 被移除，所有接收端停止播放，本地媒体轨道结束。
- 单设备发送失败时可以只重试或移除该设备，其他设备持续接收。
- 停止分享后所有 sender 和本地轨道释放，再次开启不会复用失效轨道。
- 远端单路与宫格播放、来源切换、声音播放解锁和关闭接收正常。

### 4.1 统一目标设备选择

- 附近设备列表支持明确多选，并持续显示已选择设备数量。
- 没有选择设备时，文件、文字和音视频发送入口全部禁用。
- 即使只有一台在线设备，也不会自动选中或自动发送。
- `全选` 只在用户点击后生效，`清空` 会同步禁用所有发送入口。
- 新加入设备默认不选中；设备离开后自动从选择集合移除。
- 切换设备/直播页签保留选择，离开或切换房间清空选择。

### 4.2 逐设备连接诊断

- 每台已连接设备独立显示质量摘要；多设备之间 RTT、码率、FPS 和缓冲数据不能串值。
- 诊断面板分别显示链路、视频发送、视频接收和音频指标，不用单个 RTT 冒充端到端画面延迟。
- 码率、FPS、丢包、平均接收缓冲和平均解码耗时按相邻样本增量计算；字段缺失显示 `--`。
- 候选类型只根据 selected candidate pair 判断局域网直连、公网直连或 relay，无法确认时显示未知。
- 状态等级需要连续采样防抖，数值刷新不能引发布局抖动。
- 停止媒体、设备离开或 PeerConnection 关闭后停止对应高频采样并清理定时器。
- 复制出的诊断信息不包含 SDP、IP 地址、ICE candidate 原文或房间凭据。
- 大屏侧栏与小屏 accordion 展开后，设备选择和发送操作仍可使用。

### 5. 本地缓存与刷新

- 主题、设备名称、信令地址和 STUN 设置刷新后恢复。
- 不缓存房间中的敏感传输内容和仍在运行的媒体轨道。
- 刷新后页面从稳定初始状态渲染，不闪现旧房间或旧直播画面。

### 6. 响应式与可访问性

- 大屏和小屏下房间头、设备列表、发送区、往来区和直播区不溢出、不重叠。
- 软键盘弹出和可视视口高度变化时，输入与主要操作可见。
- 所有 icon button 有可访问名称，键盘焦点和 Esc/关闭行为符合控件类型。

### 7. 发布后检查

- 发布前比较本地文件 SHA-256；发布后解压数据库内容并再次比较。
- 确认数据库内容使用 `CMP:v1:gzip:<base64>`，`modify_at` 为 Unix 秒整数。
- 打开线上分享页验证 iframe 标题、关键 UI、控制台错误和至少一次双设备连接。
