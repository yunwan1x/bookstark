# BookStark Android Flutter 重写计划（设计草案）

本次范围：设计计划和高保真界面原型；不改现有 Android、Go 服务、数据库或线上部署。原型中的内容均为示例，不代表功能已经实现。

## 1. 已确认的现状

- Android 入口：`android/app/src/main/java/com/bookstark/app/MainActivity.java`。Java Activity 加载 WebView，解压并启动 Go 可执行文件，在手机内访问 `127.0.0.1:18089`。
- 手机本地数据库为应用私有目录中的 `bookstark.db`；现有 APK 不能直接视为单纯的远程网页客户端。
- Go 服务已有登录、笔记/文章、书籍目录、待办、书签、主题、文件、分享、AI 和 TTS 等接口，见 `routers/router.go`。
- 登录使用 Cookie，写入接口受 CSRF 保护；Flutter HTTP 请求也必须完整处理，不能仅保存一个 JWT 字符串。
- AI 对话支持 SSE；`POST /api/ai/tts/stream` 返回 NDJSON，`audio` 事件携带 base64 MP3 字节，另有完成/错误事件。现有浏览器采用 MSE 播放并提供回退。
- 内容类型还包含 HTML、表格、画板、思维导图和富文档。不能在迁移时全部转换成 Markdown。
- 设计基线：`static/css/variables.css` 的蓝色主色、Slate 灰阶、4px 间距体系和标准圆角；必须支持中文、英文。

## 2. 建议的产品边界

Android 优先，使用 Flutter 原生页面重写常用操作；保留 Go 作为现有服务器后端。手机本地常用内容由 Flutter 数据层访问 SQLite，不再把启动手机内 Go 子进程作为原生首页的前提。

保留两个明确的数据来源：

1. **本地空间**：离线笔记、书籍/章节、待办、书签、附件及搜索。
2. **服务器空间**：配置服务器并登录，通过现有 API 访问该账号的内容。

两者在界面上标明来源，首版不承诺透明双向同步。复制/导入到另一空间必须是明确操作；后续如需双向同步，单独设计版本冲突、删除和附件一致性。

AI 和 EdgeTTS 是联网功能。本地空间没有配置可用联网服务时，展示连接设置入口，不伪装成可离线运行。服务器 API 密钥不随 APK 打包。

## 3. 信息架构与原型

底部导航：**首页 / 知识 / 收藏 / 文件 / 我的**。

| 页面 | 内容和主要交互 |
|---|---|
| 首页 | 继续阅读、最近内容、AI 助手；回复渲染 Markdown；生成时可停止；复制、朗读、保存笔记 |
| 知识 | 笔记、书籍、待办、文章四个分类；搜索、标签、排序；书籍进入章节树 |
| 收藏 | 书签、主题收藏入口；区分本地收藏与公开/服务器内容 |
| 文件 | 本地附件、服务器文件/WebDAV 入口；预览、上传、下载、系统分享 |
| 我的 | 当前空间/服务器、登录、语言、主题、缓存、导入导出、账户和应用设置 |
| 笔记编辑 | 标题、Markdown 编辑/预览、格式工具栏、附件；草稿恢复；明确已保存/保存失败 |
| 阅读器 | 章节目录、阅读进度、字体和主题；选文摘录；阅读与朗读联动 |
| 听书播放器 | 上/下一段、暂停继续、停止、语音、倍速、定时；后台和锁屏控制 |

本次四屏原型：01 首页与 AI、02 知识管理、03 Markdown 编辑、04 阅读与听书。后续补登录/空间切换、文件、搜索、错误/空白/加载状态和深色模式；当前四屏不是全部功能清单。

延续现有设计 token；原生触摸目标至少 48dp，正文支持系统字体缩放、TalkBack。底部操作避开手势区和软键盘。阅读和编辑页面隐藏全局导航，减少干扰。

## 4. 技术方案

- Flutter UI + ViewModel/状态层 + Repository 数据层；按知识、阅读、AI、音频、文件、账户组织功能。
- 本地 Repository 使用 SQLite 和应用私有附件目录；远程 Repository 使用 Go HTTP API。两种实现保持统一业务接口和明确数据来源，不靠页面自行判断存储位置。
- Flutter 的颜色、字号、间距、圆角、对话框、提示、列表、空状态、Markdown 阅读组件集中定义，供各页面复用；网页 JS/CSS 组件不能直接复用为 Flutter Widget。
- Cookie 会话、CSRF、过期登录和切换服务器集中管理。凭据使用 Android 安全存储；Cookie、缓存、搜索和附件按账号/服务器隔离。
- SSE 解析处理跨网络分片的 UTF-8 和事件边界；停止按钮真实取消当前 HTTP 请求，保留客户端已显示内容，并兼容服务端对取消消息的持久化语义。
- TTS 适配层逐行解析 NDJSON，解码 MP3 字节，经支持增量输入的原生音频数据源送入 Android 播放器。优先验证 Media3 的增量 MP3 数据源，而不是先选定一个只接受完整文件的 Flutter 插件。
- TTS 默认使用有界内存队列并施加背压，不持久保存完整音频文件。若平台插件必须落临时文件，先验证替代路线并明确说明实际缓存行为，不把落盘方案称为纯内存流。
- 后台播放使用 Android 媒体会话和前台媒体服务，处理耳机拔出、音频焦点、锁屏、系统回收；网络中断和用户暂停分别建模。
- HTML 和复杂编辑器先提供受限 WebView 兼容入口；限制导航和原生桥接能力。需要旧手机内 Go 路由的页面逐项审计：没有可用离线入口时，先保留旧版承载或明确标为服务器功能，不能直接删除旧能力。
- 不把后台管理、服务器资产管理和复杂办公编辑器的 Flutter 原生改写放入首个交付批次；保留可用入口，另列功能覆盖表。

## 5. 实施顺序与验收

| 阶段 | 工作 | 验收条件 |
|---|---|---|
| 0：盘点与风险验证 | 内容/接口/附件和权限清单；迁移样本；AI SSE 与 TTS 最小真机验证 | 确认数据库压缩/加密内容格式；真机在流结束前发声；取消能终止上游；确认签名和应用私有数据迁移条件 |
| 1：应用骨架 | Flutter 工程、设计 token、中英文本地化、导航、SQLite、本地/服务器空间、Cookie+CSRF 登录 | 本地冷启动不依赖 Go 子进程；断网可打开本地内容；服务器登录和过期处理正确；账号数据不混用 |
| 2：知识闭环 | 笔记/文章、书籍目录和阅读、待办、书签、搜索、附件、草稿 | 离线创建→编辑→重启→搜索→阅读闭环；Markdown 常见语法和图片正确；保存失败不显示成功 |
| 3：AI 与听书 | AI Markdown 流式回复、停止、保存；EdgeTTS 流式输入、播放器、后台/锁屏控制 | 分片首音在响应结束前出现；停止后不继续播；持续长文内存稳定；重连无重复段；手机锁屏和切应用能控制播放 |
| 4：扩展功能与兼容 | 文件/WebDAV、主题、分享；复杂内容兼容页；按盘点清单补齐入口 | 旧 HTML/表格/画板等可访问或明确受限；上传下载和 Android 分享可用；中英和深色模式检查通过 |
| 5：迁移与交付 | 原数据迁移演练、APK 真机回归、性能测量、签名和回滚 | 笔记数、章节树、附件关联与内容摘要校验一致；取消/失败可重试；旧备份可恢复；用户确认后再替换旧 APK |

## 6. 数据迁移和回滚

- 开发初期使用独立测试应用和样本数据，不覆盖用户现有 APK 或手机数据库。
- 同包名且同签名才可能直接升级读取旧私有目录；签名不匹配时走用户导出/导入流程，不能要求卸载旧应用后再想办法取数据。
- 导出必须先安全停止手机内旧后端，或使用 SQLite 在线备份 API；同时处理 WAL 和附件，不复制运行中的单个 DB 文件冒充完整备份。
- 在副本上解析旧数据，保留 ID、父子目录、时间、标签、密码/加密标记、editor_type、压缩格式和附件引用。数据格式不支持时给出逐项报告，不静默丢弃。
- 导入校验成功后才切换新数据库；原始导出保留供回滚。服务器空间与本地空间不能未经用户确认相互覆盖。

## 7. 验证重点与暂未确定项

- 行为测试：迁移失败/重试、断网草稿、服务端版本冲突、登录失效、SSE 拆包/取消、TTS 截断/取消/后台恢复。
- 真机测试：Android 手势、键盘遮挡、返回键、文件选择、分享、通知权限、锁屏播放、低内存和进程恢复。
- 性能先记录旧版冷启动、内容滚动、AI 首字、TTS 首音和长文内存的实测基线，再比较新版，不预设未经测量的速度承诺。
- 开始改写前仍需确认：现有 APK 签名是否可用、手机实际本地数据量和内容类型、服务器功能在独立本地模式下的覆盖方式、流式音频插件或原生桥接方案。
- 本设计未执行 Flutter 实现、数据迁移、APK 构建或线上部署。当前原型只是视觉设计，不可点击。
