# WebRTC HTML 核心场景回归测试计划

适用对象：分享页内嵌的 WebRTC 屏幕共享/标注 HTML 工具，以及从分享页 iframe 提取后继续修改的独立 HTML 文件。

修改该 HTML 时，如果改动影响连接、信令、屏幕采集、标注、聊天、文件传输、成员状态、画布渲染、本地缓存、移动端布局或导出相关逻辑，必须按本计划回归受影响主流程。若新增或调整主流程，先更新本文档，再按更新后的计划测试。

## 测试环境

- 使用两个独立浏览器页面模拟主控端和观看端。
- 自动信令测试需要 WebSocket 信令服务。
- 本地直开 HTML 时，线上信令服务可能因 Origin 白名单拒绝 `127.0.0.1`，可使用本地临时信令服务验证 HTML 协议流程。
- 浏览器测试建议使用 Chromium，并开启 fake media / fake screen capture 参数，避免权限弹窗阻塞自动化。

## 测试范围

### 1. 自动房间连接

步骤：

1. 主控端打开页面。
2. 打开连接面板。
3. 点击共享屏幕。
4. 点击创建房间，记录房间号。
5. 观看端打开第二个页面。
6. 切换到观看端。
7. 输入房间号并加入房间。
8. 主控端点击 `关闭房间`，观察主控端、观看端和信令服务的完整关闭过程。
9. 等待超过首轮自动重连间隔，再次检查两端连接和房间可用性。

预期：

- 主控端状态显示屏幕源已可用。
- 主控端自动信令连接成功。
- 观看端自动信令连接成功。
- 观看端连接状态为 `CONNECTED` 或等价成功状态。
- 主控端客户端数量变为 `1`。
- 自动信令模式下，主控端客户端列表默认收起，只显示观看端数量；展开/收起按钮使用三角箭头图标，不显示 `展开` / `收起` 文字；点击展开后能看到观看端状态和断开操作。
- 主控端不显示全局连接质量面板；展开客户端列表后，每个观看端 item 在连接时长后显示独立质量数据，格式为加粗 `label: 值`。
- 多个观看端同时存在时，每个观看端 item 的质量数据独立采样，不复用第一个连接的数据。
- 客户端 item 的行内质量数据刷新时字段位置稳定：RTT、FPS、码率、编码、丢帧等数值变化不能造成整行横向抖动。
- 主控端未开房时房间区域主按钮显示 `创建房间`；创建成功后同一按钮显示 `关闭房间`。
- 主控端开房后，连接面板里的“观看端”角色按钮不可点击，提示语义指向关闭房间。
- 主控端点击 `关闭房间` 后自动信令和客户端断开，“观看端”角色按钮恢复可点击，按钮恢复 `创建房间`。
- 主控端关闭按钮进入一次性的 `正在关闭` 状态，关闭事务期间不可重复点击；`close-room` 必须在清空 room/socket 状态前发送且最多发送一次。
- 服务端返回 `room-closed`、WebSocket close 与关闭超时同时或乱序发生时，本地清理保持幂等，不重复提示、不重新建立房间。
- 服务端没有返回回执或 socket 在发送前已不可用时，主控端必须显示 `关闭未确认`，不能把本地清理伪报成服务端已确认关闭。
- 观看端连接房间后，连接面板里的“主控端”角色按钮不可点击。
- 观看端未连接时房间主按钮显示 `加入房间`；加入成功后同一按钮显示 `断开连接`。
- 观看端点击 `断开连接` 后，“主控端”角色按钮恢复可点击，按钮恢复 `加入房间`。
- 房间号输入框下方始终显示当前自动信令状态文本，小屏下不依赖 hover 也能看到完整状态。
- 房间状态使用用户能理解的任务语言：主控端显示 `未开启`、`开启中`、`已开启`、`已加入 N 人`、`房间占用`、`连接中断` 或 `恢复失败`；观看端显示 `未加入`、`加入中`、`已加入`、`房间不存在`、`主控已关闭`、`重名` 或 `连接中断`。
- 房间状态解释文字直接说明下一步动作，例如复制房间号、换房间号、确认房间号或让主控端重新创建房间；默认 UI 不依赖 `自动信令`、`WebSocket`、`peer` 等技术词表达状态。
- 观看端断开连接后，主控端房间仍保持在线，页面不包含连接恢复面板，后续观看端仍可重新加入。
- 自动信令断开时，不显示连接恢复 tab/面板，只通过房间旁边状态 label 和房间号输入框下方状态文本显示失败状态。
- 主控端没有主动断开、没有停止共享时，自动信令 WebSocket 意外断开后会按退避策略自动重连，成功后状态显示为重新连接。
- 主控端点击 `断开连接`、执行 `stopAll()` 或停止房间后，不触发自动信令重连。
- 主控端创建房间前会检查 `room + peer=host` 是否可用；同名主控端房间已存在时，不发起 WebSocket，直接提示房间号被占用。
- 观看端加入房间前会检查目标房间是否存在；没有活跃主控端时不打开 WebSocket，直接提示房间不存在。
- 主控端主动关闭房间时，观看端收到关闭事件并自动断开，麦克风、摄像头、反向共享和信令状态都被清理。
- 如果观看端没有收到 `room-closed`、只收到自动信令 WebSocket 被动关闭，也要恢复 `加入房间` 按钮并显示主控端已关闭房间。
- 关闭完成后房间可用性检查返回不存在；等待超过首轮自动重连间隔后，主控端和观看端都不能自动重连已关闭房间。
- 观看端主动断开、主控端只停止屏幕或只停止摄像头时不得发送 `close-room`，主控房间继续存在。
- 主控端确认切换角色和页面 `pagehide` 时也发送关闭语义；观看端切换角色只退出当前房间，不关闭主控房间。
- 第二个同名观看端加入时，主控端拒绝接入，观看端显示“名称已存在”错误，主控端客户端数量不增加。
- 第二个同名观看端修改名称后再次点击加入，应复用当前信令连接重新发送接入申请，不因旧 peer unregister 延迟触发 409。
- 主控端 outbound 视频帧数、字节数持续增长，观看端 inbound 视频帧数、字节数同步持续增长，不能只出现首帧或静止帧。
- 观看端加入房间后仍可点击“开启麦克风”，开关麦克风不需要重连房间；开麦后按钮显示本地声音电平。
- 观看端开麦后，观看端 outbound audio 字节数持续增长，主控端 inbound audio 字节数持续增长。
- 主控端和观看端不再显示独立“启用收听”按钮，连接能力用 `接收声音`、`同步画布消息`、`接收视频流` 三个 checkbox 表达，默认全部开启。
- 主控端和观看端可以通过 `接收声音` 控制远端声音播放；收到语音后能播放远端声音，关闭后停止播放，重新开启后恢复或给出清晰的浏览器解锁提示。
- 主控端开启麦克风后，主控端 outbound audio 字节数持续增长，观看端 inbound audio 字节数持续增长。
- 主控端开启麦克风后，按钮与观看端使用相同的四段实时音量波形；说话时波形变化，关闭麦克风、关闭房间和切换角色后波形、分析节点与定时器立即清理。
- 主控端不共享屏幕时，可以直接开启摄像头；摄像头作为主视频源显示在本地 canvas，并通过同一路 outbound 视频发送给观看端。
- 主控端共享屏幕后可以开启摄像头画中画；摄像头画面合成到同一路 outbound 视频中，主控端本地和观看端都能看到右下角画中画。
- 摄像头画中画右下角缩放手柄的可点击热区足够触控，但可见手柄保持小尺寸、半透明，不遮挡小屏摄像头主体。
- 主控端屏幕共享画面静止时，摄像头画中画仍应持续刷新，本地 canvas 和 outbound output canvas 都不能因为屏幕源无新帧而停住。
- 如果屏幕源已有未返回的 `requestVideoFrameCallback`，开启摄像头画中画后不能被旧屏幕 pending 阻塞，必须重新由 `cameraVideo` 注册和驱动下一帧。
- 屏幕共享中停止屏幕共享时，如果主控端摄像头仍开启，应回落到仅摄像头主视频源；点击关闭摄像头或执行 `stopAll()` 时才释放摄像头 track。
- 观看端先加入房间，主控端后分享屏幕时，观看端能看到持续增长的视频帧。
- 主控端停止共享后，本地 canvas 立即切回 idle/空白画布状态，不能残留上一帧共享画面；再次共享前不能显示旧视频帧。
- 主控端停止共享后再次分享屏幕时，观看端视频帧继续持续增长，不能卡在旧画面。
- 主控端客户列表中每个客户都有 `视频`、`标注`、`声音` 和 `断开` 控制；自动房间模式和高级手动 SDP 模式都要存在，且排版不能挤压溢出。
- 主控端客户列表的在线状态显示连接持续时长，例如 `已连接 · 00:03:12`，并且至少每秒刷新，不显示固定不动的连接时刻。
- 主控端关闭单个客户的 `标注` 后，该客户不能再同步标注/画布消息，重新开启后恢复；关闭 `视频` 或 `声音` 只影响该客户，不影响其他客户。
- 观看端主动点击断开连接时，主控端客户列表立即删除该观看端。
- 观看端页面关闭且成功发出离开消息时，主控端客户列表立即删除该观看端。
- 观看端 WebSocket 异常断开、心跳超时或手动 SDP PeerConnection 失败时，主控端客户列表先保留该观看端并显示离线/等待重连状态。
- 离线保留期间，视频、标注、声音和文件发送等能力控制不可用，只保留移除操作。
- 离线保留窗口内同 peer 重新接入时，主控端复用原客户列表项，恢复在线状态并保留原能力权限。
- 离线保留窗口超时后，主控端自动删除该观看端。

### 1.0 观看端最终视频画布刷新

步骤：

1. 主控端共享持续运动的屏幕，观看端加入并确认远端视频和 Canvas 都持续更新。
2. 检查承担最终观看流解码的 `#remoteVideo`，确认它仍在 DOM 和渲染树中，但只占 `1×1 CSS px` 且不参与点击和页面布局。
3. 模拟 `requestVideoFrameCallback` 注册成功但回调不返回，同时保持远端轨为 `live`，并让 `video.currentTime`、presented frame 或 inbound decoded frame 继续增长。
4. 保持上述状态至少 2 秒，记录远端媒体进度、独立观看端 RAF tick、Canvas 有效绘制和最长停顿。
5. 恢复媒体帧回调，确认不重建 PeerConnection、不重复启动 RAF 或帧订阅，并继续播放。
6. 连续执行 VIEW 切换、缩放、手工具拖动、标注、全屏、横竖屏、页面隐藏/恢复、停止/重开共享和断开重连。

预期：

- 最终观看 video 不能使用 `display:none`、`visibility:hidden`、`opacity:0` 或脱离 DOM；`1×1` 活跃解码盒不能产生可见像素、页面空隙、滚动条或点击遮挡。
- `requestVideoFrameCallback` 只负责报告媒体新帧，不能成为观看端 Canvas 获得下一次绘制机会的唯一入口。
- 观看端连接且远端视频轨为 `live` 时最多存在一个 viewer RAF 和一个远端媒体帧订阅；断开、切换角色、替换轨道或销毁页面后必须全部取消。
- 媒体帧回调停顿但远端视频进度仍增长时，独立 RAF 看门狗继续绘制最新帧，最长可见停顿不超过 `150ms`；不能复制旧帧伪装真实媒体 FPS。
- 观看端 Canvas 以最高 `30 FPS` 绘制；视频运动时有效绘制 FPS 不低于 `min(远端 presented FPS, 30) × 90%`，视频静止且没有标注、弹幕或演示动画时不能持续空转全画布 60 FPS。
- 页面从后台恢复、切换全屏/横竖屏或修改视图后必须立即重绘最新远端帧，标注坐标和缩放状态保持不变。
- Chromium 可选择使用 `MediaStreamTrackProcessor` 直接消费最新 `VideoFrame`，但不支持该 API 的浏览器必须稳定使用“活跃 video + RAF 看门狗”，不能失去画面刷新。
- 桌面 Chrome、手机 Chrome 和 Safari/WebKit 至少各验证一次；自动房间、手动 SDP、声音、双向标注、聊天和文件传输不得回归。

### 1.1 视频会议模式与多摄像头合成

步骤：

1. 主控端在应用设置把观看端摄像头模式切换为 `视频会议模式`。
2. 主控端创建房间，两个观看端分别加入。
3. 两个观看端不共享屏幕，分别开启摄像头。
4. 让摄像头内人物持续移动至少 10 秒，确认主控端显示两路独立摄像头，其他观看端接收主控端合成后的会议画面。
5. 主控端开启内容完全静止的屏幕共享，继续移动摄像头画面至少 10 秒。
6. 把屏幕共享内容改为持续滚动或播放动画，比较摄像头流畅度，静态屏幕和动态屏幕不能出现明显帧率差异。
7. 确认共享屏幕成为主画面，两路摄像头进入独立席位区。
8. 停止主控端屏幕共享，确认画面恢复摄像头宫格并继续流畅更新。
9. 允许一个观看端反向共享屏幕，确认该屏幕成为主画面，其他摄像头席位保留。
10. 切回 `屏幕讲解模式`，确认恢复“先共享屏幕、再开启摄像头画中画”的现有流程。
11. 增加第三个观看端接收最终合成流；主控必须运行在独立 Chrome 进程中并真实切换到后台标签页，确认主控实际进入 `document.hidden`，持续观察至少 30 秒。覆盖 `document.hidden` getter 的测试只能验证分支，不能作为后台性能验收。
12. 分别在无共享屏幕、静止共享屏幕和播放视频共享屏幕下重复主控后台测试，并用同一 10 秒时间窗记录摄像头上行、主控 inbound、video presented、合成提交、主控 outbound 与第三观看端 inbound 的分辨率、FPS 和码率。
13. 让主控真实保持后台超过 5 分钟，再验证已有观看端持续接收、新观看端加入、摄像头关闭重开以及恢复前台；记录各阶段 track ID 和 sender 数量。
14. 在单路摄像头且无共享屏幕时确认使用原生媒体直通；加入第二路摄像头或共享屏幕后切换为多源合成，随后退出附加源并恢复直通。
15. 原生直通时检查所有主控视频 sender 的 track id 都等于唯一摄像头源轨；切换到双摄像头合成后都等于 Canvas 轨，恢复直通后回到原摄像头轨，整个过程 sender 数量不增加。
16. 客户端条目显示 `原生直通/画布合成` 发送路径状态，同时保留链路、RTT、FPS、码率、编码和丢帧六项固定质量网格。

预期：

- `屏幕讲解模式` 和 `视频会议模式` 是主控端控制的房间级互斥设置，默认仍为 `屏幕讲解模式`。
- 主控端通过房间策略消息把当前模式同步给所有观看端；观看端只展示当前房间模式，不自行覆盖主控设置。
- 每个观看端连接时预先建立独立 `屏幕槽` 和 `摄像头槽`，模式切换和摄像头开关使用 `replaceTrack`，不临时追加媒体轨道、不要求重新加入房间。
- `屏幕讲解模式` 下摄像头仍合成进该观看端的屏幕轨道，独立摄像头槽保持空闲。
- `视频会议模式` 下观看端可以不共享屏幕直接发送摄像头；观看端同时共享屏幕和摄像头时，两路媒体保持独立。
- 主控端为每个观看端分别保存 `incomingScreenStream` 和 `incomingCameraStream`，一条轨道结束不能误清理另一条轨道。
- 即使 `ontrack` 早于 `viewer-media-slots`，未知轨道也要先暂存，收到 mid/stream 映射后再绑定，不能按到达顺序串到错误槽位。
- 主控端仍只向每个观看端发送一路最终合成视频，观看端之间不建立摄像头 mesh 连接。
- 有共享屏幕时默认使用“屏幕优先”布局：共享屏幕在完整会议画布内按原始宽高比最大化显示，不再固定切走约 22% 宽度作为摄像头席位区。
- “屏幕优先”先把摄像头放入共享屏幕 `contain` 后自然产生的上下/左右留白；留白不足时再使用右侧或底部的小型浮动席位条，席位条不能反向压缩共享屏幕主区域。
- 主控端可显式切换到“分栏”布局以获得完全无遮挡的摄像头席位；布局切换不能裁剪共享屏幕，也不能改变已有标注相对共享屏幕的位置。
- 摄像头加入、离开、开关、翻页和活动成员变化不能改变“屏幕优先”下的共享屏幕主区域尺寸，避免画面跳动和标注漂移。
- 没有共享屏幕时摄像头按 1 人全屏、2 人分栏、3~4 人 `2×2`、5~9 人 `3×3` 显示。
- 会议摄像头最多 9 路；第 10 路必须收到明确拒绝并停止投递，不能继续隐藏解码。
- 会议合成最高 24 FPS，超过 4 路摄像头时最高 15 FPS。
- 没有共享屏幕、共享屏幕完全静止以及共享屏幕持续运动三种情况下，只要存在会议摄像头，就由单一会议合成时钟稳定驱动最终画面；摄像头不能依赖屏幕轨道产生新帧后才更新。
- 1~4 路会议摄像头使用最高 24 FPS 的单一合成时钟，5~9 路使用最高 15 FPS；各视频新帧回调只更新最新源状态，同一时钟时间片最多合成和提交一次。
- 会议模式默认“清晰优先”二次输出最高为 1280×720/24 FPS，避免主控多观看端重复编码压垮合成时钟；用户显式选择 1080p、2K 或原始分辨率时仍按所选目标执行，逻辑画布和标注坐标不得随编码尺寸变化。
- 1~4 路会议摄像头时，连续 10 秒内每路摄像头的接收帧、解码帧、video presented 帧、主控合成帧和第三观看端最终接收帧都持续增长；单路有效帧率不得低于 18 FPS，正常前台页面不得出现超过 150ms 的周期性停顿。
- 使用同一摄像头分别搭配静止共享屏幕和播放视频的共享屏幕时，第三观看端最终接收 FPS 差异不得超过 10%。
- 主控房间仍在推流且存在会议摄像头时，主控标签页进入后台不能停止会议合成；第三观看端最终接收 FPS 不低于主控前台的 85%，不得稳定退化为 1 FPS。
- 主控后台时实际接收分辨率不应无原因从 1280×720 降到 640×360；若浏览器平台确实限制后台媒体处理，主控端必须明确提示保持前台，不能静默输出 1 FPS。
- 单路摄像头且无共享屏幕时，最终媒体不依赖 RAF、页面定时器、Worker 定时器或 Canvas `requestFrame()`；主控后台后最终观看端仍至少接收 18 FPS。
- 多源合成如果使用 Track Processor/Generator，必须由媒体帧驱动并及时释放 `VideoFrame`；不支持该媒体管线的平台持续显示前台要求，不得把 Worker 定时器方案当作后台通过。
- 主控前台/后台、原生直通/多源合成切换均复用既有 PeerConnection 和 sender；track 切换不能新增 transceiver、产生媒体反馈环或要求重新加入房间。
- 观看端把 dummy 摄像头轨道替换为真实摄像头后，必须重新应用摄像头发送参数；摄像头轨道使用运动内容提示，会议合成输出优先保持帧率，屏幕轨道继续使用文字细节优先策略。
- 多路摄像头同时产生新帧时只合并为一次会议画布重绘，不为每路摄像头创建独立高频全画布定时器；关闭摄像头、离开房间和切换模式后对应帧回调必须解除。
- 同一时刻只允许一路屏幕作为主画面；新的观看端屏幕请求仍需主控确认。
- 屏幕内标注只映射到共享屏幕主区域，摄像头席位数量变化后标注仍贴合原屏幕内容。
- 主控本地摄像头管理 UI 可以位于最终视频画布之外；观看端接收的最终合成只包含共享屏幕、选定的摄像头浮动席位和标注，不编码主控端控制面板。
- 输出目标切换为 720p/1080p/2K 时，只改变编码画布尺寸，不改变 1600×900 会议逻辑坐标和标注位置。
- 主控端关闭某个观看端的视频权限、观看端关闭摄像头、浏览器回收摄像头 track 或观看端离开时，对应席位及时移除，其他画面不闪黑。
- 模式切换时：
    - `屏幕讲解 → 视频会议`：已有观看端屏幕和摄像头拆分到独立槽位，连接不中断。
    - `视频会议 → 屏幕讲解`：无屏幕依附的观看端摄像头停止并显示原因；有屏幕的摄像头重新作为画中画合成。
- 自动房间和手动 SDP 都协商同样的媒体槽，并读取同一房间模式。
- 刷新缓存后默认模式、主控设置、摄像头按钮启用状态和席位布局恢复正确。
- 房间内点击恢复默认设置时必须走同一模式状态机，向观看端广播屏幕讲解策略并替换媒体 sender，不能只改本地字段。
- 观看端远端摄像头 video 必须挂载在不可见但保持活跃的解码容器中，不能使用 `display:none` 或脱离 DOM 的 video 作为唯一帧时钟。
- 摄像头存在时不能等待真实帧回调停顿超过阈值后才补帧；会议合成时钟必须持续按目标帧率消费各 video 的最新可绘制帧，不能回落到固定 250ms、约 4 FPS 的刷新，也不能依赖运动屏幕替摄像头驱动合成。
- 主控客户端诊断必须按摄像头对应的 inbound RTP/mid 读取接收 FPS，不能用第一条 outbound video 统计代替观看端摄像头状态。

### 1.1.1 屏幕讲解模式主控摄像头原始轨直通

操作步骤：

1. 主控端保持 `屏幕讲解模式`，创建自动房间，只开启本地摄像头，不共享屏幕。
2. 加入两个观看端，检查两端都能连续看到主控摄像头。
3. 记录主控原始 camera track id、每个观看端对应 sender track id、sender 数量和 transceiver 数量。
4. 保持摄像头开启并开始共享屏幕，确认画面切换为“屏幕 + 摄像头画中画”。
5. 停止屏幕共享，确认恢复仅摄像头画面。
6. 关闭摄像头后重新开启，确认使用新的 live camera track，观看端恢复画面。
7. 重复快速切换摄像头与屏幕共享，并让一个观看端中途断开、重连。
8. 在手动 SDP 模式重复步骤 1～6。

预期结果：

- 仅摄像头、无屏幕共享时，主控所有活动 video sender 的 track id 都等于原始 camera track id；链路不经过 `outputCanvas.captureStream()`，Canvas 输出泵和会议合成时钟不驱动该媒体轨。
- 开始屏幕共享后切换到讲解模式媒体合成轨，屏幕与摄像头 PiP 同时可见；停止屏幕共享后恢复同一条仍存活的原始 camera track。
- 轨道切换统一使用现有 sender 的 `replaceTrack()`；整个过程 sender、transceiver 和 PeerConnection 数量不增加，观看端不用重新入房。
- 关闭摄像头后不能继续发送 ended track；重开后所有 sender 最终指向新 camera track，旧异步切换结果不能覆盖新状态。
- 多观看端共用一次摄像头采集，不为每个观看端 clone track 或重复请求权限；单个观看端断线/重连不影响其他观看端。
- 质量诊断显示“摄像头直通”，真实源分辨率与编码分辨率含义清楚；直通 track 使用运动内容提示，输出目标不能把源画质虚报为升采样后的分辨率。
- 数据通道标注、聊天、弹幕、麦克风和文件传输不受影响；标注在观看端本地叠加的位置与主控一致。
- 仅摄像头直通持续 30 秒时，观看端有效接收 FPS 不低于摄像头源 FPS 的 90%，不能依赖主控 Canvas 刷新维持摄像头运动。

### 1.1.2 屏幕讲解模式静止屏幕与摄像头 PiP 合成

操作步骤：

1. 主控端保持 `屏幕讲解模式`，共享内容完全静止的屏幕，再开启本地摄像头画中画。
2. 让摄像头内人物持续运动 10 秒，分别记录摄像头输入、讲解合成、主控 outbound 和两个观看端 inbound FPS。
3. 保持摄像头运动，把共享屏幕切换为持续滚动或播放动画，再记录相同的 10 秒数据。
4. 移动、缩放摄像头 PiP，切换输出分辨率并把主控页面切到后台 30 秒。
5. 停止屏幕共享，确认切到原始摄像头直通；重新共享静止屏幕，确认恢复讲解合成。
6. 让观看端反向共享静止屏幕并开启其摄像头 PiP，持续移动摄像头画面；同时记录该观看端 camera 上行、观看端合成输出、主控接收、主控转发和第三观看端接收 FPS，重复步骤 2～5。
7. 在自动房间与手动 SDP 下分别执行，并让一个观看端中途断开后重连。

预期结果：

- “屏幕 + 摄像头 PiP”使用媒体帧驱动的讲解合成轨；摄像头新帧使用缓存的最新屏幕帧完成合成，不依赖屏幕内容变化、主线程 RAF 或普通定时器维持输出。
- 静止屏幕和运动屏幕两个 10 秒窗口内，最终观看端有效接收 FPS 差异不超过 10%；24 FPS 摄像头源下，讲解合成和最终接收不低于 20 FPS，最大可见停顿不超过 150ms。
- 主控本地组合与观看端反向分享组合均使用同一套 presentation pipeline；观看端 camera track 的真实媒体帧必须驱动其本地合成，不能等待观看端共享屏幕的新帧。主控转发反向分享时不能再经过会降频的二次主线程 Canvas 泵。
- 观看端静止屏幕场景下，该观看端 camera 上行、观看端合成输出、主控接收、主控转发和第三观看端最终接收在同一 10 秒窗口内均持续增长且不低于 20 FPS；诊断必须能明确指出首次降帧所在阶段和对应 track/mid。
- PiP 拖动、缩放和输出尺寸改变只更新合成配置，generator track、sender、transceiver 和 PeerConnection 保持稳定，观看端不黑屏、不重新入房。
- 停止屏幕共享后恢复原始 camera track；关闭摄像头后恢复屏幕输出。快速切换时不能残留旧 Worker、writer、processor clone、RAF 或 Canvas pump。
- 不支持媒体 Worker 的兼容路径由摄像头真实帧回调驱动手动 Canvas 提交，并显示“兼容合成”；不能静默回落到约 1 FPS。
- 诊断可同时识别屏幕输入、摄像头输入、合成输出、编码和接收 FPS，链路显示“讲解合成”，避免把合成停顿误报为网络问题。
- 双向标注、VIEW、缩放、手工具、声音、聊天、文件、截图和录制保持正常；视频会议模式现有直通和多源合成不受影响。

### 1.2 视频会议布局编辑模式

步骤：

1. 主控端切换到 `视频会议模式`，建立包含共享屏幕和至少 3 路摄像头的会议画面。
2. 不进入布局编辑，尝试拖动摄像头。
3. 点击会议工具栏 `布局编辑`，依次选中、拖动和缩放不同摄像头。
4. 置顶一个摄像头，再置顶另一个摄像头。
5. 把两个摄像头拖到互相重叠的位置，并将其中一个拖到共享屏幕区域中的已有标注下方。
6. 对一个摄像头执行 `还原位置`。
7. 执行 `恢复自动布局`。
8. 分别在大屏横向、小屏竖向和纯摄像头宫格场景重复编辑。
9. 编辑过程中切换 720p/1080p/2K 输出，观察主控预览和观看端最终视频。
10. 编辑过程中让当前摄像头成员断开，再关闭主控房间。

预期：

- 非布局编辑态摄像头不响应布局拖动，标注和画布平移维持现有行为。
- 只有主控端显示布局编辑入口、选择框、缩放手柄和操作条；观看端只看到最终合成画面。
- 进入编辑态后，选中摄像头显示成员主色边框；桌面端使用四角等比缩放，小屏使用右下角单手柄和至少 `44×44px` 触控热区。
- 摄像头可以移动到会议合成画布任意位置并覆盖共享屏幕，但不能越出合成画布；共享屏幕自身不能移动或缩放。
- 摄像头之间允许重叠；最近编辑项层级稳定，唯一置顶摄像头始终在其他摄像头上方。
- 摄像头覆盖共享屏幕后，独立标注层仍显示在摄像头之上；主控端和观看端的标注可见性一致，不新增观看端布局编辑控件。
- 拖动、缩放过程实时更新主控预览和 `outputCanvas`，不能只在 pointerup 后跳变。
- 布局使用 `0~1` 归一化坐标；720p/1080p/2K 只改变编码像素，不改变摄像头相对位置和大小。
- 置顶摄像头使用最高层级并保持在当前可见页；同一时刻只允许一个置顶成员，置顶新成员会替换旧成员。
- `还原位置` 只清除当前摄像头 override；`恢复自动布局` 清除当前布局场景所有 override、置顶和选择状态。
- 有共享屏幕横屏、有共享屏幕竖屏、纯摄像头宫格分别保存会话级布局；场景切换不能误套其他场景矩形。
- 自定义摄像头覆盖共享屏幕后，`videoWorldRect` 和屏幕标注坐标保持不变。
- 新成员使用空闲自动席位，不重排已有自定义摄像头；离开成员的 override、选中和置顶状态及时清理。
- 编辑中 track ended、成员断开、切换模式、关闭房间或刷新都会结束当前 drag，不遗留控制点或非法矩形。
- 点击 `完成` 或按 `Esc` 退出布局编辑后，自定义布局保持但控制点隐藏；标注和画布平移恢复。
- 自动房间、手动 SDP、双向标注、观看端反向共享、麦克风、聊天和文件传输继续通过。

### 2. 双向标注同步

步骤：

1. 自动房间连接成功后，主控端切到标注面板。
2. 主控端在画布画一笔。
3. 观看端确认标注数量更新。
4. 观看端切到标注面板。
5. 观看端在画布画一笔。
6. 主控端确认标注数量更新。
7. 主控端和观看端分别使用作者筛选 select：`全部`、`只看自己`、`主控端` 或具体成员。
8. 主控端切换作者显示模式：`关闭`、`选中`、`始终`。
9. 使用选择工具从空白区域拖拽框选多个标注。
10. 选中一个矩形/箭头/文字标注，拖动旋转手柄调整角度。
11. 创建多个重叠标注，分别执行上移一层、下移一层、置顶和置底。
12. 使用直线工具创建一条长期直线标注。
13. 双击矩形、圆形和椭圆内部添加居中文字。
14. 选中带文字的矩形、圆形或椭圆，通过对象操作面板里的 `文字` 按钮再次编辑文字。
15. 双击箭头和直线，确认不会打开文字编辑框。

预期：

- 主控端画第一笔后，两端都显示 `标注 1`。
- 观看端画第二笔后，两端都显示 `标注 2`。
- 标注位置与鼠标/触摸落点一致，不出现明显坐标偏移。
- 观看端发出的标注携带坐标基准信息，在其他观看端或主控端不同画布尺寸下会按当前画布缩放，位置保持一致。
- 作者筛选使用自定义下拉，不使用原生 select；默认触发按钮显示 `全部`，选项包含 `自己`、`主控` 和当前出现过的观看端成员。
- 开启 `只看自己` 后，主控端只显示主控端创建的标注，观看端只显示该观看端创建的标注；总标注数量不丢失。
- 选择 `主控端` 或具体成员后，只显示该作者创建的标注；状态栏显示 `标注 N · 显示 M`。
- 视频流只传底层画面，标注由各端本地叠加，显示过滤不影响其他端的过滤状态。
- 作者显示模式是本地偏好，不同步给其他端；按钮使用紧凑图标和 tooltip/aria-label 表达 `关闭`、`选中`、`始终`，不显示 `作者: 关闭` 这类长文字；`选中` 只给当前选中标注显示作者，`始终` 给所有可见标注显示作者。
- 空白拖拽框选会显示选择框，抬起后选中所有与选择框相交的标注。
- 多选时参数面板显示已选数量，只展示可批量修改的颜色、粗细和透明度。
- 多选或选中对象时显示独立 `对象操作` 面板，且不嵌在 `工具参数` 面板内。
- `对象操作` 面板按 `编辑`、`层级`、`变换`、`排列` 分组展示复制/粘贴、组合/打散、上移/下移/置顶/置底、翻转和对齐能力；禁用项保留位置但不可误触。
- 旋转手柄显示在选框上方，拖动后标注保存 `rotation` 字段；大屏/小屏同步后角度一致。
- 旋转后的标注仍可命中、移动、缩放、删除和导出。
- 标注层级以绘制顺序表达：后绘制/数组靠后的标注在视觉上更上层，重叠命中时优先选中更上层标注。
- 上移一层、下移一层、置顶、置底会改变遮挡关系，并同步到其他端；撤销/重做可以恢复层级顺序。
- 直线属于长期图形标注，支持创建、命中、移动、两端点调整、旋转、复制、粘贴、多选、层级调整、作者筛选、截图、录制和导出。
- 矩形、圆形和椭圆支持内嵌文字字段，文字居中显示，长文本会在图形内部自动换行并按空间缩小字号，不撑大图形。
- 图形内嵌文字编辑框按文字内容自适应大小，短文字不会铺满大图形；输入、删除和粘贴时实时调整，超过图形安全区域后在编辑框内部滚动。
- 已有内嵌文字的图形再次双击或点击对象操作面板 `文字` 按钮，可以编辑原文字；空内容保存会删除内嵌文字。
- 内嵌文字随图形一起移动、缩放、旋转、复制、组合、层级调整和删除，并通过现有标注同步消息同步给其他端。
- 箭头和直线不支持添加文字：双击不打开文字编辑框，选中时对象操作面板不显示 `文字` 按钮，旧数据里的线段 `labelText` 不再渲染。

### 2.5 视频底图和大画布 world

步骤：

1. 主控端接入屏幕共享或远端共享视频流。
2. 检查 canvas 尺寸和视频底图尺寸。

4. 在 VIEW 操作菜单中执行 `显示全部内容`，适配视频和自由画布内容。
5. 使用滚轮缩放，确认缩放围绕光标进行。
6. 按住空格或中键拖动画布平移。
7. 在 board 工具条打开 `手` 型平移开关，左键/单指拖动画布平移。
8. 手型平移开启后，点击画笔、矩形或文字等图形标注工具。
9. 再次打开手型平移，点击激光笔等演示讲解工具。
10. 在视频区域内绘制矩形、箭头或手写。
11. 平移到视频外区域，在视频旁边绘制矩形、文字或手写。
12. 观察大量视频外标注时的渲染流畅性。
13. 检查标注工具区不再显示 `手` 工具，board 工具条最左侧显示手型平移开关、跟随主控视图开关、背景下拉、VIEW 操作菜单和带 `缩放` label 的缩放下拉。
14. 检查背景下拉只有 `白板` 和 `黑板`，不显示默认/default/流程 board。
15. 检查 VIEW 使用纯操作菜单：工具栏触发按钮固定显示 `视图`，菜单只提供 `回到视频`、`显示全部内容` 两个命令，不把上一次命令显示为当前持续状态。
16. 使用缩放下拉切换 25%、100%、400% 等比例，再使用滚轮缩放，确认二者控制同一套内部 worldZoom。
17. 观看端开启 `跟随主控视图`，主控端平移/缩放后观看端视口同步；观看端本地拖动或滚轮缩放后自动停止跟随。
18. 依次执行 `回到视频` 和 `显示全部内容` 后，检查目标内容 bounds 的左上角对齐规则；随后手动缩放或拖动画布，触发按钮仍显示 `视图`，不能残留误导性的适配状态。
19. 开启视频流后，确认只自动执行一次 `回到视频`，VIEW 触发器仍显示 `视图`。
20. 打开网格后，将画布拖到远离原点或负坐标区域，确认当前视口仍铺满网格。
21. 开启手型平移并保持按下拖动，在拖动过程中使用滚轮缩放，再继续移动指针；检查缩放锚点和后续拖动连续，不出现跳回旧 pan 基线。
22. 分别在手型平移、标注移动/缩放/旋转和摄像头 PiP 移动/缩放过程中触发全屏切换、window resize、横竖屏切换及 visualViewport resize；检查活动拖动被统一收口，后续 pointermove 不会继续旧操作。

预期：

- 视频流不会把整个 canvas 改成视频原始尺寸；视频只是 world 画布里的底图对象。
- 视频底图在 world 坐标中使用 canonical rect，默认 `x=0`、`y=0`、`w=sourceVideoWidth`、`h=sourceVideoHeight`，不依赖本地 `board.width/height`。
- 观看端收到远端视频流时，优先使用 data channel 里的 `source-layout.width/height` 作为 canonical `videoWorldRect`，不能只用远端视频帧尺寸。
- 输出分辨率或性能档位改变远端视频帧尺寸时，`source-layout` 不变，标注仍贴合源视频内容。
- 视频底图保持原比例完整显示，不拉伸、不裁切。
- world 尺寸至少覆盖当前可视 canvas 的 3 倍宽高。
- board 工具条的 `适配视频` 能快速回到视频底图区域，并让视频区域约占当前 canvas 视口的 99%，不裁剪、不改变视频宽高比。
- 有视频流或视频源尺寸变化时，自动执行一次 `回到视频`；同一视频 layout 下用户手动平移/缩放后，不被反复自动拉回。
- board 工具条的 VIEW 操作菜单能定位视频底图和视频外自由画布内容。
- board 工具条在窄宽度下，`跟随主控视图` 和 `网格叠加` 按钮不换行、不挤压相邻控件，完整含义通过 tooltip/title 提供。
- board 工具条里的手型平移、跟随主控视图、网格叠加、聊天浮层按钮使用统一 canvas 图标，不直接显示 `手`、`⇄`、`#`、`聊` 等文字/Unicode 字符。
- board 工具条里的手型平移、跟随主控视图和网格叠加 canvas 图标必须在按钮盒内水平、垂直居中；手型平移使用简洁的平移/移动视图图标，不使用细节复杂的手掌图标。
- 第二栏折叠或内容区全屏时显示标注悬浮按钮栏；悬浮栏支持拖动、折叠/展开和常用工具切换，并与完整标注面板工具状态同步。
- VIEW 是命令菜单而不是状态 select：触发按钮固定显示 `视图`，菜单只显示 `回到视频`、`显示全部内容` 两个真实动作，不显示 `适配窗口`、`自由视图` 或上一次执行结果。
- 点击任一 VIEW 命令后菜单关闭并恢复焦点，触发按钮仍显示 `视图`；手动滚轮缩放、缩放下拉、手型平移和远端跟随视口都不需要维护伪造的 VIEW 选中状态。
- 执行 `回到视频` 后，视频 bounds 左上角对齐当前视口左上角，视频完整可见，且保持原始宽高比。
- 执行 `显示全部内容` 后，视频和所有标注的整体 bounds 左上角对齐视口左上角安全边距，全部内容完整可见。
- world 网格按当前 `viewportWorldRect()` 可见范围绘制，不被固定 `worldSize` 裁剪；拖到远处或负坐标区域仍显示连续网格。
- 标注工具区只保留创建或编辑标注的工具；手型平移属于 board 视图开关，显示在 board 工具条最左侧，不使用 `data-tool="hand"`。
- `跟随主控视图` 开关紧挨手型平移开关；主控端禁用，观看端可开启。
- 观看端开启跟随后会应用主控端广播的 `worldPan/worldZoom`；观看端任何本地视图操作都会自动退出跟随。
- board 工具条背景下拉只暴露 `白板` 和 `黑板`；旧 `default/grid/flow` 缓存应自动兼容到白板/网格叠加，不再在 UI 中出现。
- board 工具条缩放下拉前显示 `缩放` label，控制内部 worldZoom，不再控制外层 CSS 宽度。
- 缩放下拉包含 `25 / 50 / 75 / 100 / 125 / 150 / 200 / 300 / 400`，内部 worldZoom 允许范围为 `10%` 到 `400%`。
- 滚轮缩放和缩放下拉控制同一套 worldZoom，UI 显示必须同步。
- 手型拖动中发生滚轮缩放时，以滚轮处理后的 `worldPan/worldZoom` 和当前指针视觉坐标重新建立拖动基线；继续拖动的 pan 误差小于 `0.5px`，不能用 pointerdown 时保存的旧 pan 覆盖缩放锚点修正。
- pan/zoom 后继续绘制，落点必须准确，不出现标注偏移。
- 打开手型平移开关后，左键/单指拖动只平移画布，不新增标注，不产生 undo 记录。
- 手型平移开关不改变当前选中的标注工具；关闭后恢复当前矩形、画笔、选择或橡皮擦行为。
- 手型平移开启时，点击任意图形标注工具或演示讲解工具会自动关闭手型平移，随后画布点击按新工具行为执行。
- 点击手型平移按钮本身仍能正常开启和关闭手型平移。
- 全屏、window resize、orientationchange 和 visualViewport resize/scroll 会统一结束或提交当前 board 指针事务；`worldPanning`、`editAction`、`cameraPipEditAction`、selection box 和未完成 draft 不得跨视口变换残留。
- 已发生的标注移动/缩放/旋转在视口变化时只提交一次并同步一次；尚未完成的临时 draft 取消，不生成畸形标注或额外 undo 记录。
- 左侧连接、标注、聊天、活动和设置入口使用统一 canvas 图标，不直接显示混杂 Unicode 字符；tooltip/title/aria-label 仍提供完整语义。
- 新建普通标注统一存 world 坐标，不再按视频内/视频外区分同步坐标系。
- 旧 `space="video"` 且带 `videoBaseRect` 的标注会迁移到 canonical world 坐标，迁移后按 `space="world"` 处理。
- 跨越视频边界的矩形、箭头和手写路径不拆分、不重映射，按统一 world 坐标同步。
- world 模式只绘制当前视口附近标注，大量视口外标注不能造成明显卡顿。
- 默认情况下，主控端使用滚轮、空格/中键或 `手` 工具平移缩放本地 world 视口时，观看端本地视口不跟随主控端移动。
- 观看端开启 `跟随主控视图` 后，主控端本地视口变化会同步到该观看端；关闭或本地打断后恢复自由查看。
- 主控端和观看端的视频帧仍持续增长，双向标注、显示过滤、作者标签、演示工具和手动 SDP 不受影响。

7. 在全屏和折叠状态下分别把视口切换为 `844×390` 横屏，再切回竖屏，重复拖动和工具切换。

- 未进入会议布局编辑模式时，会议布局提示与底部操作条必须保持隐藏，不能错误占用快捷工具条的可拖安全区；进入布局编辑后再参与底部避让。

- 快捷工具按钮点击后与完整标注面板保持同一 active 状态；矩形、箭头、文字等工具在旋转画布上的实际落点继续由 `canvasVisualPoint()` 处理，不能因工具条坐标调整产生偏移。
- 快捷工具条按钮保持 `26×26px` 的紧凑尺寸，按钮间距和 bar padding 不超过 `2px`；图标清晰居中，hover/active/focus 不引起尺寸跳动。
- 快捷工具条包含多边形、弹幕和橡皮擦；三者复用完整标注面板的同一工具状态和行为，不建立第二套绘制逻辑。

- 新增按钮导致宽度不足时只允许工具区横向滚动，不换行；末尾折叠按钮和右侧第二栏恢复按钮都保持可点击且不互相遮挡。
- 展开/折叠快捷工具条自身后，尾部按钮始终可见、居中且可再次展开；紧凑按钮在真实小屏下仍能稳定点击，不发生相邻工具误触。
- 工具条展开/折叠按钮使用 `aria-expanded` 和 `aria-controls` 表达工具组状态，不使用标注工具的 `active/aria-pressed` 选中语义。
- 浅色和深色主题下，工具条折叠成单按钮后展开图标必须清晰可见；不能出现 canvas 图标与按钮背景同色而表现为空白框。
- 自动房间、双向标注、观看端反向共享、视图跟随、会议模式和手动 SDP 主流程继续通过。

### 2.8 小屏滚动条隐藏与滚动能力

步骤：

1. 使用 `390×844` 竖屏打开连接、标注、聊天、活动和设置面板，制造足够内容使第二栏产生纵向溢出。
2. 检查 rail tabs、内容工具条、标注快捷工具、状态栏和会议操作条的横向溢出区域。
3. 打开成员较多的作者筛选菜单，再打开包含长内容的 modal，并触发软键盘或 `visualViewport` 高度变化。
4. 分别通过触摸/滚轮/键盘滚动纵向区域，通过横向手势或 Shift+滚轮滚动横向区域，访问首尾内容。
5. 切换到 `844×390` 横屏和内容区全屏后重复步骤 2~4。
6. 恢复 `1366×820` 大屏，检查主题滚动条。

预期：

- `max-width:860px` 下页面内部所有滚动容器的 Firefox `scrollbar-width` 为 `none`，WebKit/Blink `::-webkit-scrollbar` 不显示且不占据宽高。
- 隐藏滚动条只影响视觉；存在溢出时 `scrollTop/scrollLeft` 可正常变化，触摸、滚轮、键盘和脚本滚动都有效。
- 存在纵向溢出的第二栏和 modal 在右边缘显示 `2px` 无轨道位置指示条；存在横向溢出的工具条、rail 和状态栏在底边显示同规格指示条。
- 初始状态就能看到低对比位置指示和未到达方向的边缘阴影；用户不需要先滚动一次才能知道内容可滚。
- 起点只显示终点方向阴影，中间同时显示两端阴影，终点只显示起点方向阴影；指示条长度和位置与实际滚动比例一致。
- 提示层不拦截点击或滑动，不占布局空间，不覆盖 sticky 工具按钮、右侧恢复按钮或 modal 底部操作。
- 动态创建的作者筛选菜单和 modal 内容可被自动发现；modal 打开后只显示 modal 内滚动提示，底层提示暂时隐藏。
- 内容区全屏时提示层跟随 fullscreen root，退出全屏后恢复到页面根节点，不被浏览器全屏层级裁掉。
- 第二栏、modal、横向工具条和状态栏能够访问全部内容，sticky 按钮、保存/确认操作和右侧安全区不被裁掉。
- 横竖屏、全屏和软键盘高度变化后不出现页面整体滚动、局部滚动锁死或位置异常跳转。
- 大屏恢复现有主题滚动条，不应用小屏隐藏规则；滚动提示节点、ResizeObserver、MutationObserver 和相关窗口监听全部销毁，不在桌面后台持续扫描 DOM。

### 3.1 多观看端反向共享申请采用最新申请优先

步骤：

1. 主控端创建房间，A、B、C 三个观看端加入。
2. A、B、C 在主控端作出选择前依次发起共享屏幕申请。
3. 确认主控端只保留 C 的确认框，并检查 A、B 的观看端提示与按钮状态。
4. 让 A 先成功共享，再由 B 申请；分别测试主控拒绝 B、允许但 B 取消浏览器授权、允许且 B 成功开始共享。
5. 重复测试同一观看端连续点击申请、待确认申请人断线和已批准候选断线。
6. 在仍有待确认申请时关闭房间，再重新创建房间。
7. 在高级手动 SDP 下用两个观看端重复连续申请和活动共享源切换。

预期：

- 主控端同一时间只展示最新申请人的确认框；B 替换 A、C 替换 B 前，旧申请人分别收到一次明确的“申请已被替换”通知并退出等待状态。
- 同一成员重复申请不向自己发送替换通知，也不创建重复状态。
- A 已经共享时，B 仅提出申请不能停止 A；拒绝 B 或 B 取消浏览器授权后，A 继续作为当前画面源。
- 每次批准携带一次性 request id；只有批准候选和 request id 同时匹配的 `viewer-screen-started` 才有效，未批准成员伪造 started 必须被拒绝。
- 只有 B 真正发送匹配的 `viewer-screen-started`，且主控端远端 video 已接入并出现首帧后才切换主画面；切换成功后 A 收到停止通知并结束采集，最终只保留 B 一路活动共享。
- B 没有媒体流、首帧超时或浏览器权限取消时，A 保持活动且不收到停止通知。
- 待确认申请或已批准候选断线时只清理对应状态，不能误停当前活动共享。
- 允许、拒绝、被替换和停止通知都发送到正确的原始 data channel，不能回复错成员，也不能让成员永久停留在等待状态。
- 关闭房间、切换角色、`stopAll()` 或信令重置后，待确认申请、已批准候选和确认框全部清空；新房间不继承旧状态。
- 自动房间和高级手动 SDP 使用同一最新申请优先语义。
- 小屏确认框从顶部滑出，最新申请人和允许/拒绝操作完整可见。

### 4. 协作聊天与成员列表

步骤：

1. 自动房间连接成功后，主控端打开聊天 tab。
2. 观看端打开聊天 tab。
3. 检查两端在线成员列表。
4. 展开和收起在线成员列表。
5. 主控端发送一条广播消息。
6. 观看端发送一条广播消息。
7. 检查聊天消息条目样式和消息头。

预期：

- 在线成员列表默认折叠，只显示标题、人数和展开按钮。
- 点击展开后能看到主控端和观看端成员，再点击可以收起。
- 主控端能看到自己和已连接观看端。
- 观看端能看到主控端、自己和房间内其他观看端。
- 主控端发送消息后，观看端消息列表出现该消息。
- 观看端发送消息后，主控端消息列表出现该消息。

- 聊天表情面板宽度不能被标题行裁切，常规桌面侧栏里至少显示 4 列，小屏下不超出视口左右边界。

- 多观看端场景下，观看端消息经主控端广播给其他观看端。
- 未连接的观看端不能发送消息，并给出明确提示。
- 聊天消息不使用完整卡片外框或大块背景，只用轻量间距/分隔表达列表。

### 5. 成员文件传输

步骤：

1. 自动房间连接成功后，主控端和观看端都打开聊天 tab。
2. 确认没有传输任务时不显示文件传输 panel。
3. 在应用设置里确认单文件大小上限默认是 `50` MB。
4. 展开在线成员列表。
5. 主控端在成员列表中选择一个观看端，点击文件按钮。
6. 选择一个小于上限的文件。
7. 观看端在文件传输列表中点击接收。
8. 等待传输完成。
9. 观看端点击下载。
10. 使用测试 channel 在接收确认前发送 chunk，并分别注入错误发送者、越界索引、错误 total、重复/冲突 chunk、非法 base64 和超额数据。
11. 分别在缺少 chunk、收到完整 chunk、成员断线和关闭房间时发送 `file-complete`。
12. 并发发送两个声明大小合计超过当前文件上限的 offer，随后拒绝或完成第一个再重试第二个。

预期：

- 文件按钮只出现在非自己的成员上。
- 没有传输任务时，文件传输 panel 不显示，也不显示“还没有文件传输”的空状态。
- 有等待接收、发送中、接收中或完成任务时，文件传输 panel 自动显示。
- 文件大于当前设置上限时不发送，并提示超过上限。
- 观看端收到文件邀请后可以接收或拒绝。
- 接收后显示传输进度。
- 传输完成后接收方显示下载按钮。
- 分享页 iframe 内点击下载按钮能触发浏览器下载；如果浏览器策略阻止下载，页面必须显示可点击备用下载链接或明确错误提示。
- 点击下载后，该传输项隐藏；所有传输项隐藏后，文件传输 panel 整体隐藏。
- 发送方状态显示已发送。
- 观看端发给其他观看端时，文件由主控端中转；不要求第一版建立观看端之间直连。
- 修改单文件大小上限后，下一次选择文件立即按新上限校验。
- incoming transfer 必须绑定原始 offer 的发送者；其他成员即使知道 transfer id，也不能注入 chunk、伪造完成、取消或错误状态。
- 用户点击接收前不能保存任何 chunk；接收后只接受 `0 <= index < expectedChunks` 且 `total` 与本地预计算值完全一致的分片。
- chunk 大小按 base64 实际解码后的字节数校验，不能信任远端 `payload.size`；累计字节不得超过 offer 声明大小和本地设置上限。
- 重复索引不能重复累计；相同内容可忽略，冲突内容按协议错误终止传输。
- 只有全部索引完整且实际累计字节严格等于声明大小时，`file-complete` 才能生成 Blob 和下载按钮。
- 非法 chunk 或非法 complete 会让单个传输失败、通知正确发送方并立即释放分片与接收预算，不影响房间和其他合法传输。
- 所有等待接收、接收中及已完成待下载 Blob 的大小合计不能超过当前接收预算；任务拒绝、取消、失败、下载、移除和关闭房间后预算立即释放。
- 接收端长期保存解码后的二进制分片，不保存整文件 base64；生成 Blob 后立即清空分片和索引，Blob 保留期间继续计入预算，避免 base64 与 Blob 双份占用或连续完成文件绕过上限。
- 文件发送者在接收完成后断线不能把任务改成失败；Blob 和下载按钮保持可用，直到下载、关闭或自动隐藏。
- 正常文件下载后的内容哈希与源文件一致；零字节、单 chunk、多 chunk 和接近设置上限文件都能通过。

### 8. 信令配置读取

步骤：

1. 在 BookStark 中配置 WebRTC 信令服务器参数。
2. 打开 WebRTC HTML。
3. 检查页面使用的信令地址和 ICE servers。
4. 主控端创建自动房间后保持空闲一段时间。
5. 观看端断开后重新加入同一个房间。
6. 模拟或等待服务端清理 stale WebSocket 后，主控端自动重连并复用原房间号。

预期：

- 页面优先读取 `/api/webrtc-signaling/config` 返回的 `signaling_url`。
- 页面使用配置返回的 `ice_servers`，包括 STUN/TURN。
- 如果配置接口不可用，页面回退到内置默认配置，不阻塞本地预览。
- 连接质量里的 ICE 链路类型使用中文主文案：
  - `host-host` 显示 `直连 · 本地网络`。
  - `host-srflx` / `srflx-host` 显示 `直连 · 公网地址`。
  - `srflx-srflx` 显示 `直连 · NAT 穿透`。
  - 任一端为 `relay` 显示 `中继 · TURN 转发`。
  - 任一端为 `prflx` 且没有 `relay` 显示 `直连 · 动态探测`。
  - 未选中 candidate pair 时显示 `检测中`。
- 连接质量里的链路类型主文案不能省略；原始 candidate 类型如 `host/host` 应放到 title 或辅助信息中。
- 主控端的链路、RTT、FPS、码率、编码、丢帧应显示在对应观看端 item 内；观看端自己的连接质量面板保持可见。
- 客户端 item 内的质量字段按稳定 3 列排列，第一行 `链路 / RTT / FPS`，第二行 `码率 / 编码 / 丢帧`；编码尺寸完整显示，不能截断成省略号。
- 服务端 WebSocket 协议层 ping/pong 正常工作，空闲连接不会无声半开。
- stale peer 被服务端超时清理后，同名房间和同名 `host` 可以重新注册。
- 主控端没有停止共享时，信令断开后仍能自动重连，观看端后续能重新加入。

### 9. 输出分辨率与画质策略

步骤：

1. 打开 WebRTC HTML。
2. 检查画布顶部工具条的输出分辨率下拉菜单。
3. 确认默认选中 `清晰优先`。
4. 依次切换 `流畅 720p`、`高清 1080p`、`超清 2K`、`原始分辨率`、`清晰优先`。
5. 自动房间连接成功后再次切换输出分辨率。
6. 模拟网络波动触发自动降档。
7. 模拟网络恢复稳定，观察恢复提示。
8. 网络持续稳定超过多个采样周期，继续观察提示次数。
9. 手动切换性能模式后，再次观察提示状态。

预期：

- 默认值为 `清晰优先`，不会默认强制使用 4K 原始分辨率。
- `原始分辨率` 作为独立选项存在，适合本机、高带宽或 4K 屏幕场景。
- 切换输出分辨率后，`outputCanvas.width/height` 立即变化，不需要重连房间。
- 有真实视频源时，`outputCanvas.width/height` 基于真实源尺寸或 canonical source layout 计算，不以本地交互 `board` 的固定尺寸作为默认基准。
- 例如源屏幕为 `3024×1542` 时，选择 `超清 2K` 应等比下采样到接近 `2560×1305`，不能继续保持 `1600×900`。
- 源尺寸小于目标上限时不强制上采样，`原始分辨率` 尽量使用真实源尺寸。
- 输出目标尺寸变化只影响 outbound 编码画布，不改变本地 `board` 尺寸、world 坐标、标注坐标或命中测试。
- 观看端反向共享时，合成用的 `viewerCompositeCanvas` 也跟随输出目标立即重算尺寸。
- 工具条主控端使用 `输出目标`，观看端未反向共享时使用 `反向共享输出` 且禁用，观看端反向共享后启用。
- 连接质量使用 `实际编码` / `实际接收`；状态栏按角色显示 `源: ...`、`接收: ...`、`输出: ...`、`反向输出: ...` 或 `显示: ...`，避免三个尺寸语义混淆。
- 状态栏不显示裸 `SCREEN/REMOTE` 或容易和连接质量混淆的裸 `FPS`；如果恢复 FPS，必须明确为渲染 FPS。
- 发送端视频参数会重新调优，主流程连接、聊天、文件传输和标注同步不受影响。
- 自动降档后，网络恢复稳定时最多提示一次 `网络已稳定，可按需切回清晰优先`。
- 网络持续稳定时，不重复刷相同提示。
- 再次发生网络波动并自动降档后，允许下一轮恢复提示。
- 手动切换到 `清晰优先` 后，不再提示“可切回清晰优先”。

### 10. 导出与 iframe 下载能力

步骤：

1. 在本地 WebRTC HTML 中点击导出按钮。
2. 在线上分享页 iframe 中点击导出按钮。
3. 自动房间连接成功后，产生视频画面和标注，再点击导出按钮。
4. 切换白板/黑板/网格状态后再次导出。
5. 在全屏或小屏横屏状态下再次点击导出。
6. 在标注工具中点击截图按钮，分别尝试 `当前视图`、`视频区域` 和 `框选区域`。
7. 对截图分别执行 `保存 PNG` 和 `复制图片`；复制不支持时观察是否降级下载。
8. 在截图菜单中点击 `录制 WebM`。
9. 分别用当前视图、视频区域和框选区域触发录制。
10. 录制过程中观察时长、大小估算和停止按钮。
11. 等待达到时长上限自动停止，或手动点击停止。

预期：

- 本地 HTML 点击导出能下载 PNG。
- 线上分享页 iframe 内点击导出能下载 PNG；如果浏览器阻止下载，页面显示可点击备用下载链接或明确错误提示。
- 导出图片内容与当前画面一致，包括底色、网格、视频帧、标注和作者显示。
- `canvas.toDataURL()` 或下载触发失败时不静默失败，页面有 toast 或等价错误提示。
- 分享页 HTML 预览 iframe sandbox 包含下载所需能力，不影响摄像头、麦克风、屏幕共享、全屏和剪贴板既有能力。
- 标注工具里的截图按钮提示为 `保存当前画面`，点击后出现截图菜单或小屏 sheet。
- `当前视图`、`视频区域`、`框选区域` 都能生成 PNG；`视频区域` 没有视频源时给出明确提示。
- `框选区域` 拖拽时显示选择框，`Esc` 可以取消；完成框选后可保存或复制。
- 截图只捕获画布内容，不捕获左侧面板、顶部工具条、底部状态栏等外部 UI。
- 截图不新增 undo 记录，不改变 `annotations`，不触发远端同步。
- `录制 WebM` 默认使用受限配置：`15fps`、默认最长 `30 秒`、最大 `120 秒`、桌面最大宽度 `1280px`、移动端最大宽度约 `960px`。
- 点击 `录制 WebM` 后先展开录制设置，不立即开始录制。
- 录制时长支持 `10 秒`、`30 秒`、`60 秒`、`120 秒` 快捷项，也支持 `1-120` 秒自定义输入。
- 录制 fps 支持 `10`、`15`、`24`、`30`，并传给 `canvas.captureStream(fps)`。
- 输出宽度支持 `720px`、`960px`、`1280px`、自动，离屏录制 canvas 宽度不能超过所选值。
- 录制当前视图、视频区域和框选区域都能生成 WebM 下载。
- 录制中显示轻量浮层，包含录制时长、目标时长、估算大小和停止按钮。
- 录制期间不能重复开启第二个录制任务。
- 到达上限自动停止并提示。
- 浏览器不支持 `MediaRecorder` 或 `canvas.captureStream` 时显示明确提示，不静默失败。
- 录制不改变主画布尺寸，不影响标注坐标、弹幕、摄像头 PiP 和聊天浮层刷新。

### 11. view 切换和手型拖动后的标注坐标一致性

步骤：

1. 打开两个页面，一个作为主控端，一个作为观看端。
2. 让两端 canvas 可视高度不同，例如主控端受浏览器屏幕共享提示条影响，或直接使用不同视口高度。
3. 主控端创建自动房间并分享屏幕。
4. 观看端加入房间并看到视频。
5. 主控端依次执行 `回到视频`、`显示全部内容`，再使用缩放下拉和滚轮缩放。
6. 主控端开启手型拖动画布，多次平移视频所在画布。
7. 观看端也切换到不同本地 view 和缩放比例，确保两端视口不一致。
8. 主控端切回标注工具，在视频内明显参照物上绘制矩形、箭头和画笔路径。
9. 绘制位置必须覆盖视频中心、中下部和底部区域；底部区域优先使用横线、矩形框或箭头尖端作为参照。
10. 对每个测试点计算相对 `videoWorldRect` 的归一化坐标 `(x - rect.x) / rect.w`、`(y - rect.y) / rect.h`。
11. 观看端观察同一标注相对视频参照物的位置，并比较归一化坐标误差。
12. 反向共享场景下，观看端分享屏幕并绘制，主控端观察位置。
13. 手动 SDP 模式下至少验证一次远端接收 world 标注。
14. 主控端打开手型平移，按住指针拖动画布；保持拖动时滚轮缩放并继续拖动，记录滚轮处理后预期 pan 和实际 pan。
15. 分别开始画布平移、标注移动/缩放/旋转和 PiP 移动/缩放，在 pointerup 前触发全屏、resize、orientationchange 和 visualViewport resize，然后继续移动指针。
16. 检查 VIEW 触发器始终显示 `视图`，执行 `回到视频`、`显示全部内容` 以及后续自由平移缩放时都不伪装成持续选中状态。

预期：

- 新绘制标注在发送端和接收端都使用 `space:"world"`。
- `world -> canvas -> world` 往返误差应小于 0.5px。
- 接收端处理 `space:"world"` 标注时，不按本地 `board.width/board.height` 二次缩放。
- 两端以各自 `videoWorldRect` 计算标注中心的归一化位置应一致。
- 中心、中下部和底部测试点的归一化坐标误差建议小于 `0.002`；超过时需要优先检查坐标源、source layout 和 canvas CSS/backing size 是否混用。
- 主控端和观看端 canvas 尺寸不同、view 不同、手型拖动位置不同、缩放不同，都不影响标注相对视频内容的位置。

- 矩形中心、箭头端点和画笔路径点都要满足同一套归一化位置误差标准。
- `space:"video"` 旧数据仍按视频矩形映射。
- 无 `space` 的旧标注仍按历史 `baseWidth/baseHeight` 兼容缩放。
- `upsert`、`replace-all`、编辑移动、旋转、缩放和批量操作后的同步都保持一致。
- 手型拖动过程中插入滚轮缩放后，继续拖动不跳回旧 pan；自动化计算的 pan 误差小于 `0.5px`。
- 视口形态变化后所有活动 pointer 事务均已结束；额外 pointermove 不改变画布、标注或 PiP，pointerup 不产生重复提交。
- VIEW 菜单只表达定位命令，缩放、平移和跟随视角不产生过期的适配状态文字。
- 视频、标注、声音、聊天、文件传输、导出和缓存刷新不受影响。

### 35. 观看端本地 3D 场景与 3D HUD 深色主题

适用改动：

1. 自动房间中以主控端和两个观看端连接；分别让两个观看端保持平面、切到 3D，确认混合视图不会重建 PeerConnection、丢失 DataChannel 或互相改变视图。

3. 主控切换主屏、全景、发言人和席位镜头；观看端开启“跟随主控”时同步镜头，关闭后可本地环视、缩放和复位，且不改动主控或另一观看端镜头。
4. 主控和观看端分别创建、编辑、删除标注，发送弹幕与聊天；检查平面/3D 两种端侧渲染只显示一层内容，坐标、作者、颜色和生命周期一致。
5. 观看端反向共享屏幕和摄像头，主控批准后在两个观看端的平面/3D 视图中检查媒体、成员席位、发言状态和权限变化。
6. 让观看端在主控进入 3D 前加入、进入后加入、刷新缓存后重连和信令短暂断开后重连；检查房间场景快照、视图偏好和跟随状态恢复。
7. 在自动房间和手动 SDP 下重复平面/3D 往返、双向标注、反向共享、聊天、文件、录制和权限控制。
8. 在 `1440x900`、`1366x820`、`390x844` 和 `844x390` 下打开 Scene、Annotate、工具、属性、聊天和会议成员面板，连续切换浅色/深色主题。
9. 在会议成员面板验证空列表、单成员、多成员、在线、离线、发言、禁音、无权限和操作菜单；检查标题、成员行、状态、计数、滚动条、hover、active、focus 和 disabled 状态。
10. 主题切换前后记录 renderer、视频纹理、capture track、Dock 位置和折叠状态，确认只更新 HUD 外观，不重建媒体/Three.js 资源，也不修改视频或 CanvasTexture 色彩。

验收标准：

- 主控和观看端都能进入真实本地 3D 场景；观看端不是将已合成 3D 视频再次贴入场景，平面/3D 混用时媒体内容和成员状态一致。
